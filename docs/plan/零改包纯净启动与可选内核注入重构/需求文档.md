# 零改包纯净启动与可选内核注入重构（需求定稿）

> **规划版本**：`v0.3.4`（基于 `v0.3.3` 最新代码基线定稿，已实现并完成验证）
> **归档日期**：2026-11-28
> **核心目标**：在 `v0.3.3` 侧边栏统一交互基础上，默认彻底去除对官方 `app.asar` 的修改与重签名，消除用户对“修改客户端文件/签名”的合规与安全顾虑；提供 Windows / macOS 零侵入统一启动体验，同时保留侧边栏面板内的可选内核注入开关，并确保全链路无安全、沙箱、权限与升级竞态漏洞。

## 一、 配置 Schema、接口与状态机重构（核心底座）

### 1. 新增配置开关字段与持久化原子性
* 在 `config.default.json` 及 `sidecars/skin-engine/main.mjs` 的 `buildDefaultConfig()` / `normalizeConfig()` 中新增：
  ```json
  "kernelInjection": false,
  "macLauncherMode": "isolate"
  ```
* **原子化写盘**：`sidecars/skin-engine/main.mjs` 的 `writeConfig()` 升级为“写临时文件 + `renameSync` 原子替换（失败回退覆盖）”，杜绝高频滑块调节或并发保存导致 `config.json` 写半截损坏。
* **字段语义**：
  * `kernelInjection`：
    * `false`（**新装默认**）：零改包纯净模式。严禁任何脚本或守护进程主动解包、修改 `resources/app.asar` 或执行 macOS `codesign` 重签名。
    * `true`（**用户 Opt-in 开启**）：深度增强模式。允许写入 `loadingOverlay.js` 防白闪与 `dist/main.js` 调试端口开关，并允许热更新同步及退出/开机自愈。
  * `macLauncherMode`（仅 macOS 生效）：
    * `"isolate"`（**默认**）：将原版迁入索引隔离目录，启动器占用 `/Applications/Antigravity.app`，实现单搜索入口。
    * `"keep_original"`（**更新器兼容性兜底**）：保留官方原版在 `/Applications/Antigravity.app`（保证 100% 满足强校验 `/Applications` 路径的自动更新器），轻量启动器生成于 `~/Applications/Antigravity Skin.app`。
* **老版本向后兼容（严格状态对齐）**：从 `v0.3.3` 及更早版本升级首次读取配置、或用户原 `config.json` 缺少 `kernelInjection` 字段时，禁止保留隐式 `undefined` 状态，必须按真实物理状态初始化并持久化：
  * 若检测到当前 `app.asar` **已存在**旧版补丁标记（`agy-video-boot-host`）：显式初始化为 `kernelInjection: true`（确保与当前已改包状态一致），并在侧边栏面板展示一次性温和引导：“检测到您正沿用旧版内核注入补丁，v0.3.4 已支持 100% 零改包纯净模式，可随时点击一键还原官方原版”。
  * 若检测到当前 `app.asar` **无**补丁标记：显式初始化为 `kernelInjection: false`，并同步清理可能残留的旧版 Windows `Startup\AntigravitySkinSelfHeal.vbs`。

### 2. 拆解“通道状态”与“补丁状态”（消除误报）
重构 `sidecars/skin-engine/main.mjs` 的 `getBootPatchStatus()` 及 `/api/boot-patch/status`、`/api/patch-status`：
* **维度 A — CDP 插件通道健康状态（`cdpAvailable`）**：只要检测到有效的 `DevToolsActivePort` 并可连接，即视为插件通道正常。**零改包模式下，不强求 `app.asar` 存在补丁标记**。
  * **无参启动救生舱引导**：当零改包模式下启动超过 3 秒仍未探测到 `DevToolsActivePort`（例如客户端升级重置参数、从 CLI 无参拉起、或 macOS 绕过启动器拉起），`sidecars/panel` 侧边栏面板（不依赖 CDP 仍能正常运行）与可选轻提示须清晰告知：“当前未以 `--remote-debugging-port=0` 启动，主窗口换肤与汉化未激活，请使用快捷方式/启动器重启（Windows 将同步自动补全快捷方式）”。
* **维度 B — 内核防白闪注入状态（`kernelPatched` + `kernelInjection` 开关）**：
  * 当 `kernelInjection === false` 时：侧边栏面板不得显示 `patch_missing` 警告横幅，统一显示「标准零改包模式（官方原厂文件与签名完整）」。
  * 仅当 `kernelInjection === true` 且检测到客户端升级覆盖了 `app.asar` 时，才提示“补丁缺失，点击修复”。

### 3. 新增还原接口与全局安全边界加固
* **新增 `POST /api/restore-boot`（及 `/api/boot-patch/restore`）与 `panel` 双路由转发**：与 `/api/patch-boot` 对称。支持在侧边栏面板点击关闭内核注入时，写入 `features.kernelInjection = false`，Windows 同步注销自愈守护，并通过脱离父进程的辅助任务安全还原 `app.asar.bak` 后重拉起客户端；`sidecars/panel/main.mjs` 须同时在 Sidecar SDK（`app.api('/api/patch-restore')`）与独立 HTTP 预览路由中补齐 `/api/patch-restore` 转发。
* **跨平台 `antiFlash` 对称清理**：`sidecars/skin-engine/main.mjs` 的 `/api/boot-finished` 清理与 `ws.onopen` 防白闪保护不应仅限于 `process.platform === 'darwin'`，须对所有未打补丁宿主（含 Windows 零改包模式）对称生效。
* **系统级字段并发防覆写保护（`POST /api/config`）**：`features.kernelInjection` 与 `features.macLauncherMode` 属于底层系统状态字段，`sidecars/panel/app.js` 的 `collectConfig()` / 轮询同步及 `POST /api/config`（含 `sidecars/panel/main.mjs` 的 `writeSkinConfigFallback`）保存主题/壁纸等普通配置时，服务端须保留当前磁盘上受保护的系统字段（禁止用前端旧快照覆盖它们），仅允许通过 `/api/patch-boot`、`/api/restore-boot` 或专用切换接口及脚本修改。
* **已提前合入 `v0.3.3` 基线的安全基石（保持并持续守护）**：
  * 本地 HTTP 服务 `Host` / `CORS` 白名单校验（`isAllowedCorsOrigin`）；
  * `POST /api/update/apply` 初始地址与跳转域白名单校验（仅允许 `https://github.com/MrcolorH/antigravity-skin/` 及 `github.com` / `*.githubusercontent.com` 跳转）；
  * 双 CDP 引擎（`skin-engine` 的 `isMainAppTarget()` 与 `panel/compat/runtime-ui.mjs` 的 `validTarget()`）及 `i18n-engine.js` 均严格跳过认证/OAuth/登录回调路径。

## 二、 守护进程与更新链路防“偷改包”门控

1. **封堵版本变动弹窗哨兵的盲目注入引导**：
   * 在 `v0.3.3` 基线上，`sidecars/skin-engine/main.mjs` 的 `runBootPatchSentinel()` 已取消派生 `exit-heal-watcher`，改为在客户端版本号变动（`versionChanged`）时弹出“插件状态被覆盖，是否修复重新激活？”弹窗。
   * 在 `v0.3.4` 中，`runBootPatchSentinel()` 弹窗及 `exit-heal-watcher.mjs` 均必须以 `cfg.features.kernelInjection === true` 作为硬前置门控：当 `kernelInjection === false` 时，仅静默更新 `patch-sentinel.json` 中的 `lastClientVersion` 与状态，**严禁**弹出内核修复弹窗或修改 `app.asar`。
2. **在线热更新门控与白名单同步完整性**：
   * `sidecars/skin-engine/main.mjs` 执行在线更新部署后，**仅当 `cfg.features.kernelInjection === true` 时**才调用 `scripts/patch-boot-overlay.mjs` 同步补丁。
   * `extractAndDeploy()` 的 `safeFiles` 同步列表必须补全 `self-heal.bat` 与 `provisionSplash.js`（与 `scripts/install.mjs`、`scripts/pack.mjs` 对齐），并在解压/覆盖前校验目标路径未逃逸出临时目录与 `PLUGIN_ROOT`。
3. **开机自愈脚本双保险门控与批处理状态同步**：
   * `scripts/self-heal.mjs` 启动后必须先校验 `config/config.json` 中 `features.kernelInjection === true`；若为 `false`（或未启用）则直接安全退出，不做任何 `app.asar` 修改。
   * 独立脚本 `scripts/patch-boot-overlay.mjs`（含 `patch-loading.bat`）和 `scripts/restore-boot-overlay.mjs`（含 `restore-loading.bat`）在执行成功后，需同步更新 `config/config.json` 中的 `features.kernelInjection` 布尔状态，并对应联动注册或注销 Windows 开机自愈守护，避免手动批处理操作与后台自愈状态打架。

## 三、 跨平台安装与卸载架构重构

> **关键约束**：`scripts/install.mjs`、`scripts/uninstall.mjs` 与各自无 Node.js 环境下的回退脚本（`install.ps1`、`install.sh`、`uninstall.ps1`、`uninstall.sh`）**必须保持逻辑完全一致**，避免在线一行命令（`irm | iex` / `curl | bash`）走入旧逻辑；同时 `install.sh` / `uninstall.sh` 兼顾 Linux 与 macOS，所有 macOS 专属动作（`.app` 迁移、`osacompile`、`lsregister`）必须严格包裹在 `uname -s == "Darwin"` 分支内，Linux 保持更新 `.desktop`（如有）与 `~/.local/bin/antigravity` 带 `--remote-debugging-port=0` 启动。

### 1. Windows 平台改造
* **安装默认动作**：
  * **不再**自动调用 `scripts/patch-boot-overlay.mjs` 和 `scripts/register-self-heal.mjs`。
  * 扫描桌面（`Desktop` / `CommonDesktopDirectory`）、开始菜单（`Programs` / `CommonPrograms`）以及 **任务栏固定快捷方式（`%APPDATA%\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar`）** 中的 `*Antigravity*.lnk`，自动追加 `--remote-debugging-port=0`。
* **系统目录只读 / UAC 权限与重定向桌面路径兼容**：
  * 统一补全 `Programs\Antigravity IDE\resources` 至 `patch-boot-overlay.mjs`、`restore-boot-overlay.mjs`、`migrate-pulse.mjs` 的候选路径清单，与 `self-heal.mjs` 对齐。
  * 获取用户桌面与开始菜单路径时禁止硬编码 `path.join(home, 'Desktop')`（兼容 OneDrive 桌面或自定义转移路径），统一通过 Windows Shell API（`[Environment]::GetFolderPath('Desktop')` 等）解析真实目录。
  * 若客户端安装于受 UAC 保护的 `C:\Program Files\` 目录导致普通用户无法修改公共桌面/开始菜单快捷方式：在零改包默认模式下，自动于当前用户桌面与开始菜单生成带 `--remote-debugging-port=0` 的用户级专属快捷方式，严禁静默失败；若用户主动触发可选内核注入/还原且目标目录只读，应检测权限并提示或发起 UAC 提权执行。
* **客户端升级重置快捷方式自愈与零改包重拉起**：
  * 当 Windows 上 Sidecar 启动且处于零改包模式（`kernelInjection === false`），但探测到 `cdpAvailable === false`（常见于官方客户端自动更新覆盖重建了快捷方式参数）时，Sidecar 自动重新检查并补全桌面/开始菜单/任务栏 `.lnk` 上的 `--remote-debugging-port=0`，并温和提示用户重启客户端生效（全过程绝不碰 `app.asar`）。
  * `scripts/restore-boot-overlay.mjs` 必须新增 `--no-restart` 与 `--from-plugin` 两种运行参数（Win & Mac 通用）：「插件内关闭注入开关（`/api/restore-boot`）」通过 `--from-plugin` 还原 `app.asar.bak` 后自动重拉起客户端时**必须携带 `--remote-debugging-port=0`**，确保切换后皮肤与侧边栏面板依然在线；「卸载插件（`uninstall.mjs` / `uninstall.sh`）」调用时必须传 `--no-restart`，还原文件后**严禁提前重拉起客户端**（避免 macOS 后续移回 `.app` 时发生运行中目录冲突）。
  * 官方安装包自带的 CLI `resources\app\bin\antigravity.cmd` 保持 100% 零修改；若需命令行直接开启皮肤，文档注明传参 `--remote-debugging-port=0` 即可。
* **卸载与还原动作**：
  * 清理上述全部快捷方式中附加的 `--remote-debugging-port=0`（以及本插件创建的用户级补位快捷方式）。
  * 若存在开机自愈注册（`Startup\AntigravitySkinSelfHeal.vbs`），调用 `register-self-heal.mjs --unregister` 清理。
  * 若存在 `app.asar.bak`，自动调用 `restore-boot-overlay.mjs --no-restart` 静默恢复官方原厂 `app.asar`。

### 2. macOS 平台改造（零改包 + 单一入口启动器）
* **隔离原版 `.app`（保留 100% 官方签名）**：
  * 在 `macLauncherMode === "isolate"` 时，将 `/Applications/Antigravity.app` 完整迁移至索引隔离目录：
    `~/Library/Application Support/AntigravitySkin.noindex/Antigravity.app`
  * **禁止在宿主运行中原地强移自身**：若检测到脚本正在 Antigravity 内置终端中运行（`isInsideAntigravityHost` 为真）且需要搬移正在运行中的 `/Applications/Antigravity.app`，禁止直接原地 `mv`（会导致当前运行进程的包路径句柄失效），必须提示用户退出客户端或在外部终端运行安装脚本（或通过先完全脱离父进程的异步脚本等客户端退出后再迁移）。
  * 若目标移动操作受 `/Applications` 权限限制，通过 `osascript` 请求一次图形化授权弹窗（失败时可自动降级为 `"keep_original"` 并在 `~/Applications` 生成启动器，不阻塞安装）。
  * **严禁修改**原版 `.app` 内部任何文件或签名；放在用户 `~/Library/` 目录可确保当前用户具备完整读写权限，便于内置更新器就地自动更新。
* **官方手动重装覆写防呆（极重要）**：
  * 若用户日后手动从官网下载新版 `.dmg` 拖入 `/Applications/Antigravity.app` 覆盖了启动器，安装脚本及健康检查在识别到 `/Applications/Antigravity.app` 的 `CFBundleIdentifier !== com.antigravity-skin.launcher` 且后台目录已有旧副本时，**严禁用旧副本覆盖新版**，必须以 `/Applications` 下的新版官方客户端为准清理旧副本或重新迁移。
* **生成轻量启动器（`com.antigravity-skin.launcher`）**：
  * **专属防覆写标识**：启动器 `Info.plist` 必须写入独立标识（`CFBundleIdentifier = com.antigravity-skin.launcher`）及标记文件，安装/重装/补丁脚本必须据此区分“启动器”与“真·原版”，**严禁把启动器当成原版覆盖进后台目录**。
  * **外观与 Dock 体验**：复用原版 `Contents/Resources/AppIcon.icns`，设置 `LSUIElement = true`，拉起后台原版后启动器立即退出，不在 Dock 产生双图标；确保 `Applications`、Launchpad 与 Spotlight **仅搜得到 1 个入口**。
  * **LaunchServices 关联接管与防重**：启动器 `Info.plist` 继承官方 `CFBundleDocumentTypes` 与 `CFBundleURLTypes`（`antigravity://` scheme），并在迁移后台原版后执行系统自带 `lsregister -u <隔离目录原版.app>` 清除后台原版的系统“打开方式”及协议缓存登记（仅更新系统 LS 缓存，零修改 `.app` 与签名），避免右键打开文件或协议链接时出现双入口或绕过启动器无参拉起。
  * **文件拖放 / 打开方式 / URI 协议 / 架构与权限兼容**：使用 macOS 原生 `osacompile` 编译通用架构（同时兼容 Apple Silicon 与 Intel）的轻量 AppleScript `.app`（支持 `on run`、`on open` 接收拖放/打开的文件路径、支持 `on open location` 转发 `antigravity://` 协议），而不是仅用纯 `#!/bin/sh`（纯 Shell 无法接收 Finder AppleEvent）。脚本内仅使用纯 `do shell script "open ..."` 拉起目标程序，**严禁**调用 `tell application "System Events"` 等自动化指令，避免触发不必要的 macOS TCC 辅助功能/自动化隐私弹窗。执行拉起时注意参数顺序：`open -a "$REAL_APP" <文件或目录参数> --args --remote-debugging-port=0`（文件参数必须在 `--args` 之前）。生成后执行 `xattr -cr` 清除潜在隔离标记。
  * **后台原版缺失自检**：启动器拉起前若找不到目标原版 `.app`，须弹出清晰提示框指引恢复或重装，避免双击无任何响应。
  * **终端 CLI 命令适配**：更新 `install.sh` 写入 `~/.local/bin/antigravity` 的脚本，统一带上 `--args --remote-debugging-port=0`。
* **统一全项目路径寻址与迁移顺序**：
  * `locateAntigravityResources()`、`scripts/patch-boot-overlay.mjs`、`scripts/restore-boot-overlay.mjs`、`scripts/migrate-pulse.mjs`（`locateAppAsar()`）以及 `sidecars/panel/compat/platform.mjs`（`agentExecutables()`）均需将 `~/Library/Application Support/AntigravitySkin.noindex/Antigravity.app` 加入优先候选路径，且识别到 `com.antigravity-skin.launcher` 时跳过，避免误把启动器当成原版；安装时须保证旧版 `antigravity-pulse` 迁移在移动 macOS 原版 `.app` 之前执行。
  * 所有 `restartAntigravity` 逻辑（含 `patch-boot-overlay.mjs`、`restore-boot-overlay.mjs`、`install.mjs`）在 macOS 下**禁止**直接 `open -b com.google.antigravity`（会绕过启动器拉起无参原版），必须拉起启动器或显式附带 `--args --remote-debugging-port=0`；同时 `scheduleDetachedMacRestart()` 关闭原版进程时应使用 `tell application id "com.google.antigravity" to quit`，避免与启动器名称同名导致退出指令误发给启动器或白等超时。
* **卸载完整闭环（极重要）**：
  * 执行 `uninstall.sh` / `scripts/uninstall.mjs` 时：首先若存在 `app.asar.bak`（即此前用户曾手动开启过 macOS 内核注入），须在恢复原位置前先调用 `restore-boot-overlay.mjs --no-restart` 静默还原官方 `app.asar` 内容（弥补当前 `uninstall.mjs` 仅处理 `win32` 的遗漏，不提前重拉起客户端，并提示如需恢复 Apple 原厂签名须覆盖安装官方包）；随后若启动器占用 `/Applications/Antigravity.app`（必须先校验 `CFBundleIdentifier === com.antigravity-skin.launcher`，严禁误删用户自行重装的官方原版！）且后台目录存在原版 `.app`，先删除启动器，将 `~/Library/Application Support/AntigravitySkin.noindex/Antigravity.app` **完整移回 `/Applications/Antigravity.app`** 并执行 `lsregister -f /Applications/Antigravity.app` 立即恢复官方系统打开方式与协议登记；若处于 `keep_original` 模式，则仅删除 `~/Applications/Antigravity Skin.app`（并同步清理 `~/.local/bin/antigravity`）。若客户端运行于当前卸载过程中且需要移回 `.app`，先安全退出客户端再执行搬移。

## 四、 UI 交互、老用户迁移与配套清单

### 1. 侧边栏面板“内核注入”开关（全面对齐 `v0.3.3` 侧边栏架构）

## 五、 核心验收标准与边界测试用例矩阵

落地实现后，必须覆盖以下全部自动化与手工验收场景：
1. **默认零改包静态校验**：全新安装后（Win & Mac），验证 `app.asar` SHA256 哈希与原版完全一致、macOS 官方 `codesign -dv` 签名完好无损、Windows `Startup` 无自愈脚本、`runBootPatchSentinel()` 在版本变更时不弹补丁框。
2. **UI 状态无误报与沙箱合规校验**：零改包且带 `--remote-debugging-port=0` 启动时，侧边栏面板显示“零改包模式正常”，不弹出修复横幅；面板内开启/还原注入全程无原生 `confirm()`/`alert()` 阻塞。
3. **可选开关往返闭环**：面板点击开启注入 → 验证防白闪与 `kernelInjection=true` 生效；点击关闭注入 → 调用 `/api/patch-restore` → `/api/restore-boot` 还原 `app.asar.bak`、清理自愈并切回 `kernelInjection=false`；手动批处理同步改变配置状态。
4. **macOS 重装覆写与卸载还原**：模拟官网 `.dmg` 覆盖 `/Applications/Antigravity.app` 后再重装/卸载，验证不会用后台旧版覆写新版，也不会误删官方原版 `.app`；正常卸载后官方 `.app` 完整归位且 `lsregister -f` 恢复协议关联。
5. **Windows 任务栏与 UAC 目录**：验证任务栏 `.lnk` 成功写入参数；验证只读 `Program Files` 下用户级快捷方式兜底创建；验证 OneDrive 重定向桌面路径。
6. **热更新、配置并发与 CDP 安全校验**：验证 `POST /api/update/apply` 拒绝非 `https://github.com/MrcolorH/antigravity-skin/` 地址（及非法重定向域）且 `safeFiles` 同步无遗漏；验证 `sidecars/panel/app.js` 常规配置保存与轮询不会意外覆盖 `features.kernelInjection` / `macLauncherMode`；验证 `skin-engine` 与 `panel` 均跳过 `/oauth`、`/login`、`/callback` 本地认证路径。
7. **零改包模式体验无退化校验**：验证 Windows 零改包模式（无 `loadingOverlay.js` 主进程 WCO Hook）下窗口最小化/最大化/关闭按钮及顶部栏完全可见且色彩正常；验证 `/api/boot-finished` 在 Windows 零改包下同样对称清理 `#agy-macos-anti-flash`；验证切回零改包后重拉起保留 `--remote-debugging-port=0`、以及客户端升级重置 `.lnk` 后 Sidecar 自动补参数能力。

### 🌟 核心架构升级：默认全面回归「100% 零改包」纯净模式

为了彻底消除大家对“修改官方客户端文件 / 重签名”的顾虑，本版本对 Windows 与 macOS 安装架构进行了全面重构：

### 🛡️ 安全边界说明与自查提醒（重要）

1. **本插件的安全边界**
   * 本项目仅工作于**本地界面渲染层与只读本地看板**（动态壁纸、毛玻璃样式、UI 文案汉化、本地用量展示）。
   * **绝不**读取、提取或上传任何 Google 账号 OAuth Token，**绝不**拦截、伪造或代理发往 Google 服务器的 API 请求，且已对本地服务收紧 `Host` / `CORS` 与更新包地址白名单校验，严格隔离登录与 OAuth 授权页面，并移除第三方在线更新代理源。
2. **⚠️ 强烈建议自查是否存在「第三方违规调用」**
   * 近期社区反馈的 Antigravity 账号风控（如 `Error 403` / 服务禁用），主要诱因集中在**将 Antigravity OAuth 凭证接入第三方客户端、API 反代/中转代理、多号池轮询工具、高频自动化刷量脚本或高风险代理网络环境**。
   * **请务必自查**：您当前的账号或本机环境中，是否同时安装或授权过上述第三方中转代理、号池管理工具或外部桥接脚本（可前往 Google 账号的「第三方应用与服务权限」页面检查并及时撤销非官方授权），切勿将此类风险与纯本地 UI 换肤/汉化插件混为一谈。
