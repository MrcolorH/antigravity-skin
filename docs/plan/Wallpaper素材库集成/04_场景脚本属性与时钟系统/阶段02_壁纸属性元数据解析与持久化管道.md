# 阶段02：壁纸属性元数据解析与持久化管道

> **所属子模块**：子模块四：场景脚本属性与时钟系统  
> **状态**：`待开发 (Pending)` · **优先级**：P1  
> **核心目标**：实现对 Wallpaper Engine 创作者在 `project.json` 中定义的静态属性及运行时动态脚本属性的完整反射解析，并构建按壁纸 ID 隔离的独立持久化与恢复默认管道。

---

## 1. 属性元数据规范与模型

Wallpaper Engine 创作者在壁纸根目录的 `project.json` 中通过 `general.properties` 声明了素材的可调属性。典型结构如下：

```json
{
  "general": {
    "properties": {
      "schemecolor": { "order": 0, "text": "ui_browse_properties_scheme_color", "type": "color", "value": "0.1 0.5 0.9" },
      "use24h": { "order": 1, "text": "24小时制", "type": "bool", "value": true },
      "show_seconds": { "order": 2, "text": "显示秒数", "type": "bool", "value": false },
      "particle_density": { "order": 3, "text": "粒子浓度", "type": "slider", "min": 0, "max": 100, "value": 50, "step": 1 },
      "preset_mode": { "order": 4, "text": "样式选择", "type": "combo", "value": "default", "options": [{ "label": "默认", "value": "default" }, { "label": "霓虹", "value": "neon" }] }
    }
  }
}
```

---

## 2. 具体实施方案

### 2.1 后端元数据读取扩展 (`sidecars/skin-engine`)
1. 在 `wallpaper-library.mjs` 解析壁纸信息（`parseWallpaperFolder`）时，读取 `project.json` 中的 `general.properties`；
2. 属性清洗与归一化：
   - 过滤保留支持的核心类型：`bool`、`slider`、`color`、`combo`、`text`；
   - 支持多语言词条（如 `ui_browse_properties_*`）自动本地化回退映射；
   - 附带排序权重（`order`），便于前端按作者预期顺序呈现；
3. 将清洗后的 `properties` 字典挂载到壁纸对象中返回给前端。

### 2.2 客户端独立持久化模型 (`config.json`)
在客户端配置的 `features.dynamicWallpaper` 下设立专有命名空间：
```json
{
  "features": {
    "dynamicWallpaper": {
      "wallpaperUserProperties": {
        "1982409329": {
          "use24h": false,
          "particle_density": 80,
          "schemecolor": "1.0 0.2 0.5"
        }
      }
    }
  }
}
```

### 2.3 生命周期恢复与作者预设复原
1. **换壁纸自动装载**：在挂载新场景壁纸时，优先合并当前壁纸 ID 对应的 `wallpaperUserProperties`，若无则使用作者定义的 `value` 初始值；
2. **↺ 一键恢复默认（Reset to Defaults）**：
   - 提供清空该壁纸用户自定义覆盖的接口；
   - 瞬间回滚为创作者出厂预设值并即刻通知渲染器重绘。
