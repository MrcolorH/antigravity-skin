# 阶段五：展陈几何与无黑边适配

> 状态：**已实施**　|　版本：v0.3.0　|　前置：[阶段三](./阶段03_多形态渲染适配器与体验打磨.md)、[阶段四](./阶段04_双开关交互与分级筛选.md)

## 1. 需求与现象

用户反馈（原话）：

> 视频或者别的当做背景壁纸时，有的会无法全屏，或者就是跟窗口不匹配。要是单纯横竖屏素材问题还好说，但是我的素材都是横屏素材。动态控制素材展示大小的问题得控制一下，最起码得没有黑边啥的。

拆解为三条可验收目标：

| # | 现象 | 期望 |
|---|------|------|
| 1 | 部分素材无法铺满窗口 | 任何素材、任何窗口尺寸都 100% 覆盖视口 |
| 2 | 素材与窗口比例不匹配 | 由策略决定裁切 / 模糊填充 / 留边，不再出现"莫名其妙的大黑边" |
| 3 | 素材本身均为横屏，可排除竖屏因素 | 问题必须定位在渲染层，而非素材层 |

## 2. 根因定位

### 2.1 主因：`<video>` 是三种形态里唯一"裸奔"的节点

三种背景形态的几何写法在修复前并不一致：

| 形态 | 几何来源 | 是否独立于毛玻璃 CSS |
|------|----------|----------------------|
| `iframe`（网页壁纸） | `mountWeb()` 内联 `cssText` 写死 `position:fixed;inset:0;width:100vw;height:100vh` | ✅ 安全 |
| `img`（场景壁纸） | 独立注入的 `#agy-scene-style` | ✅ 安全 |
| `video`（视频壁纸） | **仅** `glass-theme.css` 里的 `#agy-dynamic-video` 规则 | ❌ 依赖注入 |

`realMountVideo()` 创建元素时只写了：

```js
videoEl.style.opacity = '1';
videoEl.style.transition = 'opacity 0.6s ...';
```

**没有任何尺寸与 `object-fit`。**

而样式注入链路本身有三处可断点：

1. `ensureStyle()` → `const cssToUse = glassThemeCss || window.__AG_SKIN_GLASS_CSS__ || ''; if (!cssToUse) return;` —— CSS 字符串为空时**直接放弃注入**；
2. `updateStyle(newCss)` → `s.textContent = newCss`，`index.js` 每次 `applyFeatures` 都会调用 `updateStyle(window.__AG_SKIN_GLASS_CSS__ || '')`，全局变量一旦丢失就把 `<style>` **内容清空**；
3. 宿主 SPA 重渲染移除 `<style>` 后，`unifiedObserver` 有 180ms 的重挂延迟，这段时间内素材完全不受控。

### 2.2 放大器：宿主 Tailwind preflight 接管裸 `<video>`

Antigravity 基于 Tailwind，preflight 中存在：

```css
img, video, canvas { display: block; max-width: 100%; height: auto; }
```

显式尺寸一旦丢失，这条规则立即接管：`<video>` 会以「内容区宽度 + 固有宽高比」渲染，且回到普通文档流。于是：

- 素材比视口**更宽** → 高度撑出视口，上下溢出；
- 素材比视口**更窄** → 上下或左右留下背景板（白 / `#131313`），即肉眼所见「黑边」；
- 窗口缩放时完全不跟随，表现为「跟窗口不匹配」。

这解释了「有的会无法全屏」——它取决于那次会话里 CSS 是否成功注入，而不是取决于素材。

### 2.3 次因：`100vw / 100vh` 含滚动条宽度

`width: 100vw` 包含纵向滚动条宽度（Windows 下约 15–17px）。页面出现滚动条时，`fixed` 元素比内容区更宽，右侧被裁并产生横向溢出。这是"就算 CSS 正常也差一点"的来源。

### 2.4 排除项

- **不是横竖屏素材问题**：用户素材均为横屏，且 `cover` 对任意比例都能铺满；
- **不是解码问题**：`videoWidth/videoHeight` 始终正常，`readyState = 4`；
- **不是 z-index 问题**：`-999999` 层级正常，遮住的是背景板而非黑屏。

> 不予解决项：素材画面内部本身烧录的黑边（例如 21:9 电影源塞进 16:9 画布）。这是像素内容的一部分，任何 `object-fit` 都无法剥离，只能靠 `cover` 放大裁掉——可通过调大裁切策略缓解，但无法无损消除。

## 3. 方案

### 3.1 统一媒体几何控制器

在 `wallpaper.js` 新增 **2.6 统一媒体几何控制器**，把 `video / iframe / scene` 的几何收口到同一处：

| 手段 | 说明 |
|------|------|
| `!important` 内联声明 | 所有几何属性直接写到元素 `style` 上，优先级高于任何选择器，含宿主 preflight 与主题 CSS |
| `top/right/bottom/left: 0` + `width/height: 100%` | 取代 `100vw/100vh`；百分比相对 initial containing block，天然排除滚动条 |
| `max-width/max-height: none` | 专门反制 Tailwind `img,video{max-width:100%}` |
| 双保险 | `glass-theme.css` 同步改写为 `inset + 100%`，但即使整份 CSS 丢失，控制器仍独立生效 |

### 3.2 四种展陈策略

新增配置 `dynamicWallpaper.fit`：

| 模式 | 行为 | 黑边 | 裁切 | 适用 |
|------|------|------|------|------|
| `cover`（默认） | 等比铺满并裁切 | 绝对无 | 有（比例越差裁越多） | 绝大多数场景 |
| `blur` | 同素材重度模糊铺满作底 + 前景等比完整显示 | 绝对无 | 无 | 比例差异极大、且不能丢画面内容 |
| `contain` | 等比完整显示 | 有（留边） | 无 | 需要看到完整画面且接受留边 |
| `fill` | 非等比拉伸铺满 | 绝对无 | 无（但变形） | 极端宽高比、且画面以纹理/渐变为主 |

配套 `dynamicWallpaper.fitPosition`（九宫格）：`center / top / bottom / left / right / top left / top right / bottom left / bottom right`，决定 `cover` 裁切时优先保留哪一侧的主体。

### 3.3 `blur` 模式的两层结构

```
#agy-dynamic-video-backdrop  (z:-999999, object-fit:cover, blur(48px) brightness(.7) scale(1.16))
#agy-dynamic-video           (z:-999999, object-fit:contain)   ← DOM 在后，压在上面
#agy-wallpaper-backdrop      (z:-1000000, 纯色底板)
```

要点：

- 两路 `<video>` 共用同一 URL，媒体缓存只下载一次；
- 层叠靠 `DOM 顺序 + 相同 z-index` 保证，规避与纯色底板（`z:-1000000`）的层级冲突；
- 低频时间轴校正（8s 一次，阈值 0.4s）防止双实例解码漂移；
- **元数据未就绪（`readyState < 1`）时不预建模糊层**，避免为坏链素材白拉一路解码管道；`loadedmetadata` 后的几何回调会自动补建。

### 3.4 视口同步

`resize` / `orientationchange` / `fullscreenchange` + `ResizeObserver(documentElement)` 三路触发，统一经 `requestAnimationFrame` 合帧，重算几何但不重建解码管道。

### 3.5 场景壁纸的动画安全边

`cover` 模式下场景图沿用 CSS 的 `inset:-2% / 104%` 安全边，供 Ken Burns 位移动画使用；但从 `contain/fill` 切回 `cover` 时必须清除运行时覆盖，否则安全边丢失、动画会露边。

**关键坑**：清除 `width/height` 的同时**不能**清除 `max-width/max-height: none`——宿主 preflight 的 `img{max-width:100%}` 会把 104% 压回 100%，实测正是由此暴露 49.95px（=1249×4%）的边缘泄漏。

## 4. 配置契约

```jsonc
"dynamicWallpaper": {
  "fit": "cover",              // cover | blur | contain | fill
  "fitPosition": "center"      // 九宫格，见 3.2
}
```

- 旧配置无这两个字段 → `normalizeConfig()` 自动补默认值，**向后兼容**；
- 非法值（含大小写/多余空格）→ 服务端与客户端双向白名单校验，静默回退 `cover` / `center`；
- `fit` 变更走 `updateFit()` 热路径，只重写几何声明，**不重建解码管道**（切换零闪烁）；
- `fit` 不参与 `mediaKey`，避免调一次下拉框就重挂视频。

## 6. 实测数据

验证方式：真实 Chrome（headless=new）+ CDP 量测，`--no-proxy-server`，模拟宿主 Tailwind preflight（`img,video{max-width:100%;height:auto}`）、强制纵向滚动条、3840×2558 真实 mp4 素材。核心场景为 **`glassThemeCss: ''`（复现毛玻璃样式完全缺失）**。

| 用例 | 期望 | 实测 | 结果 |
|------|------|------|------|
| 视频 + CSS 完全缺失 | 仍铺满视口 | video rect = 1249×625，clientW/H = 1249×625 | ✅ |
| 忽略滚动条宽度 | 宽 = clientWidth 而非 innerWidth | 1249 vs innerWidth 1264（差 15px 未被计入） | ✅ |
| 无横向溢出 | `scrollWidth ≤ clientWidth` | 1249 ≤ 1249 | ✅ |
| 视口 2400×900 动态变化 | 跟随 | video 2385×900 = clientW/H | ✅ |
| `cover → blur` | 前景 contain + 模糊层出现 | foreground `contain`，backdrop `cover` + blur(48px) | ✅ |
| `blur → cover` | 模糊层释放 | backdrop = null | ✅ |
| `fill` / `contain` | 对应 object-fit | `fill` / `contain` 原样生效 | ✅ |
| 场景壁纸 + blur | 双层生效 | `agy-scene-bg` 存在，前景 `contain` | ✅ |
| 场景切回 cover | 恢复 104% 安全边 + Ken Burns | computed width = **1298.95px**（1249×1.04），animation = `agySceneKenBurns` | ✅ |
| 坏链视频 + blur | 不拉起第二路解码 | readyState=0，backdrop 未创建 | ✅ |
| 控制台 | 零报错 | 0 exception / 0 error | ✅ |

13 项判定全部通过。

## 7. 已知边界

1. **素材内部烧录的黑边无法消除**：属于像素内容，只能靠 `cover` 放大裁剪，或改用 `blur` 让边缘不显眼。
2. **网页壁纸（`web`）只保证容器铺满**：`iframe` 没有 `object-fit` 语义，内部网页是否自适应由素材自身决定。插件不注入缩放，因为对 `100%` 自适应的网页强行 `transform: scale` 会触发重排回环。
3. **`blur` 模式为双路解码**：功耗高于单路，1080p 硬解下实测无掉帧，但不建议在集显设备长时间使用。
4. **`contain` 必然留边**：这是该模式的语义本身，不是缺陷；留边颜色跟随 `#agy-wallpaper-backdrop`（浅色主题白 / 深色主题 `#131313`）。
