# 阶段八补充方案：素材库入口由悬浮回归框内集成设计

> **状态**：方案制定 / 准备实施  
> **归属**：[阶段八：参数弹窗化、精细渲染控制与素材库悬浮入口](./阶段08_参数弹窗化与素材库悬浮入口.md) 之 **交互架构修订与性能补充**  
> **核心目标**：彻底废除 `fixed` 悬浮入口与 `syncAnchor` 实时几何计算，将素材库呼出交互深度融入「设置-外观」配置框内部，达成 **0 Layout Thrashing（零强制回流）** 与 **100% 纯 CSS 原生流式排版**。

---

## 1. 痛点诊断与性能瓶颈剖析

### 1.1 现有「悬浮书签胶囊（FAB）」的架构缺陷

在阶段八初版设计中，素材库入口被设计为吸附在大红框右外侧的纵向悬浮胶囊（`#agy-btn-open-library`，挂载在 `document.body`，`position: fixed`）。

为了实现“随外观卡片滚动并咬合在右外边线、且不出弹窗底边安全区”，系统在 `client/modules/agy-modal.js` 与 `client/modules/appearance-menu.js` 中实施了动态锚点计算（`syncAnchor`）：

```
[设置弹窗滚动容器] ──(scroll / resize 事件高频触发)──> [syncAnchor 算法]
                                                              │
    ┌───────────────── 每一帧强制回流 (Layout Thrashing) ──────┘
    ├─► targetCard.getBoundingClientRect()          [强制浏览器同步重排]
    ├─► 递归寻找 scrollParent (getComputedStyle)     [强制读取样式树]
    ├─► scrollParent.getBoundingClientRect()        [再次强制重排]
    ├─► modal.getBoundingClientRect()               [三次强制重排]
    ├─► 计算 viewTop / viewBottom / desiredTop Clamp
    └─► 写入 activeFab.style.left / top / classList [触发重绘与合成]
```

### 1.2 性能与稳定性代价
1. **主线程掉帧与滚轮卡顿**：在鼠标滚轮快速滑动或触摸板惯性滚动时，每秒触发数十次 `scroll` 事件。由于高频读写 DOM 几何属性，引起连续的 Layout Thrashing，导致设置面板滚动严重卡顿。
2. **生命周期守卫繁重且易出缝隙**：由于元素脱离卡片宿主（挂在 `body`），必须在切 Tab、弹窗关闭、卡片移出视口、双开关切换等数十处场景编写边界保护，极易出现残留幽灵按钮、位置闪烁或延迟脱节。
3. **视觉割裂感**：悬浮在卡片外部，在不同分辨率或小窗口下总有一种“外挂插件补丁”的违和感，缺乏系统原生一体感。

## 2. 融入方案设计：回归框内流式排版

### 2.1 核心设计哲学
- **从外部浮动（Floating Overlay）回归内部流式（Flow-in-Card）**；
- **从 JS 几何测量驱动回归纯 CSS 盒模型渲染**；
- **保持素材库大弹窗的独立性与多列浏览体验，仅重构其唤起入口**。

### 2.2 交互形态选型与对比

| 方案 | 交互形态 | 优点 | 缺点 | 推荐指数 |
| :--- | :--- | :--- | :--- | :---: |
| **方案 A：内嵌资产中心横幅<br>(Asset Entry Banner)** | 在素材库开关开启后，卡片内部自然展开一张精致的资产卡片横幅，展示资产数量与「进入素材库」操作按钮 | 视觉仪式感最强，信息清晰（呈现索引数量），点击区域大，完全随卡片平滑滚动 | 会占用约 48px 纵向高度 | ★★★★★<br>**(推荐主方案)** |
| **方案 B：操作行内联按钮<br>(In-line Action Button)** | 直接在现有的「当前生效素材行」加入 `[🖼 浏览素材库]` 次级强调按钮：<br>`当前壁纸 ● 落樱少女 [🖼 浏览素材库] [⚙ 设置]` | 极其紧凑，0 额外纵向占高，操作链路极短（看当前壁纸 -> 换壁纸） | 空间紧凑时文字按钮排版略显密集 | ★★★★★<br>**(推荐双轨方案)** |
| **方案 C：卡片内纯 CSS 侧贴 Tab<br>(CSS Absolute Tab)** | 保留侧边 Tab 形态，但将其直接作为卡片的 child，用纯 CSS `position: absolute; right: 0;` 定位 | 保留了原有纵向书签的视觉偏好 | 若卡片带 `overflow: hidden` 会被裁切；极窄宽度下容易遮挡卡片内部内容 | ★★★☆☆ |

## 3. 推荐实施方案：双层融入架构（方案 B + 方案 A）

为了兼顾「极致操作效率」与「清晰的资产状态展示」，推荐采用 **框内双层融入方案**：

### 3.1 外观框内部布局原型（Wireframe）

```

│ 🖥 全局动态视频壁纸                                           [ON]      │
│ ├─ 使用 Wallpaper 素材库                                     [ON]      │

│ │  └─ 📁 已索引 362 项资产 (零拷贝挂载)           [ 浏览与管理素材 → ]   │   (纯 CSS 容器，随框滚动)

│                                                                        │

│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.2 细节与交互规范

#### 1. 行内快捷按钮（方案 B：Action Slot）
- **触发位置**：在「当前壁纸展示行」和「当前开屏素材展示行」的齿轮按钮左侧，放置次级轮廓胶囊按钮：
  `<button class="agy-btn-browse-lib">🖼 浏览素材库</button>`
- **交互逻辑**：
  - 点击壁纸行的按钮，直接唤起素材库弹窗，并且预置筛选上下文为适合壁纸的资产；
  - 点击开屏行的按钮，同样直接唤起素材库弹窗，并支持一键「设为开屏」；
  - 按钮样式与原生的齿轮设置按钮同高（28px），采用淡背景与边框，优雅低调。

#### 2. 内嵌资产横幅（方案 A：Asset Entry Banner）
- **触发位置**：当「使用 Wallpaper 素材库」开关被用户拨开时，在开关下方以优雅的 `max-height` / `opacity` 过渡动画展开。
- **视觉风格**：
  - 融入卡片底色（半透明毛玻璃底 + 微弱的高光边框 `border: 1px solid rgba(255,255,255,0.08)`）；
  - 左侧展示 Wallpaper 官方图标与索引状态：
    `已索引 362 项创意工坊资产 · 零拷贝极速管线`
  - 右侧主按钮：`[ 浏览资产库 → ]`，点击直接调用 `window.__agyWallpaperLibrary.openModal()`；
  - 当开关关闭时，横幅自动收起移除，不占任何空间。

## 4. 技术改造方案与性能收益

### 4.1 彻底剥离的代码（瘦身项）
1. **删除 `syncAnchor` 机制**：
   - 从 `client/modules/agy-modal.js` 中完全删除 `syncAnchor()` 函数（节约约 85 行复杂几何计算代码）；
   - 从 `client/modules/agy-modal.js` 中删除 `.agy-lib-fab-vertical` 相关的固定定位 CSS 样式。
2. **删除事件监听器**：
   - 从 `client/modules/appearance-menu.js` 中彻底删除 `scrollContainer.addEventListener('scroll', onScrollOrResize)`；
   - 彻底删除 `window.addEventListener('resize', onScrollOrResize)`；
   - 彻底删除 `ensureFabLibrary()`、`syncFabVisibilityAndPosition()`，不再创建 `document.body` 上的 `#agy-btn-open-library`。

### 4.2 性能对比指标

| 指标 | 改造前（悬浮入口 + syncAnchor） | 改造后（框内融入 + 纯 CSS 布局） |
| :--- | :--- | :--- |
| **滚动时 JS 耗时** | 每次 scroll 约 4~12ms（多次重排） | **0 ms**（完全不触发 JS 脚本执行） |
| **Layout Thrashing** | 严重（每帧多次 `getBoundingClientRect`） | **0 次**（彻底绝迹） |
| **主线程帧率** | 滚轮滑动时可降至 35~45 FPS | **稳保 60 / 120 / 144 FPS**（由合成器负责滚动） |
| **内存与 DOM 树节点** | 跨层级挂在 `body`，脱节需维护清理 | 随卡片创建/销毁自然生命周期，0 内存泄漏风险 |
| **多分辨率与缩放适配** | 需手写 Clamp 与 Inner-dock 防溢出 | 浏览器原生 Flex/Grid 自适应，任何缩放均完美对齐 |
