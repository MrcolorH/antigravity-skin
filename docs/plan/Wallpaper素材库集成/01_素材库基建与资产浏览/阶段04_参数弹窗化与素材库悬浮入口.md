## 1. 需求背景与核心改动

### 1.1 需求演进与用户指示

用户明确指示：
> 阶段六的文档里，壁纸和开屏动效的设置里，覆盖一下帧率、渲染精度之类的。两个地方单独设置。然后剔除掉阶段七里的几个档位调节的功能。帮我把这些写进阶段六文档。然后将文档改为阶段8。
> 开屏准备完成后，自动进入首页的时间也作为配置项，放在开屏的设置里。（预设3秒，可填0~10s，0则为不手动操作不进入首页）这一点也加入到文档中。

### 1.2 阶段七遗留档位的问题诊断

阶段七引入 WebWallGL WebGL2 场景动态渲染引擎时，在外观设置菜单直接内联了一个「场景渲染」下拉选项（`agy-wrap-scene-renderer`）：
- `dynamic`：动态 · 完整效果（强制 60fps + 原生设备 DPR + high 质量）
- `eco`：动态 · 省电模式（强制 30fps + DPR 1.0 + medium 质量）
- `static`：静态海报兜底

**痛点与弊端**：
1. **粗粒度捆绑，无法按需精细控制**：用户可能希望高刷屏运行 120fps 但降低渲染精度（0.75x）以节省显存带宽；或者希望 4K 原生精度（1.0x/DPR）但限帧 30fps 压制显卡发热。阶段七的一刀切档位无法满足需求。
2. **壁纸与开屏割裂，开屏缺乏调优能力**：开屏动效同样会播放视频或场景动效，启动首屏对性能最敏感，但阶段七的档位只控制壁纸，开屏完全无法配置帧率与精度。
3. **主面板继续纵向膨胀**：在外观菜单主面板硬塞一个场景渲染下拉，让面板层级进一步拥挤，违背了「主面板保持紧凑、专业参数收归弹窗」的架构原则。
4. **开屏时序固定，缺乏手动驻留控制**：原本开屏动画无论素材长度如何，多被写死在约 3 秒后强制淡出。用户希望欣赏动效细节、或者等待手动确认后再进入首页工作区，必须提供可自定义的自动进入延时（含 0 秒纯手动驻留）。

#### 2.2.2 壁纸设置 vs 开屏设置 对比矩阵（单独设置）

| 配置维度 | 壁纸显示与渲染设置 (`dynamicWallpaper`) | 开屏动效设置 (`bootAnimationConfig`) | 独立设计考量 |
| :--- | :--- | :--- | :--- |
| **铺满方式** | `cover` / `blur` / `contain` / `fill` | `cover` / `blur` / `contain` / `fill` | 开屏独立控制比例适配，不影响壁纸展陈 |
| **对齐位置** | 九宫格对齐（默认 `center`） | 九宫格对齐（默认 `center`） | 两者独立 |
| **画面亮度** | 默认 **`0.85`**（压暗保证前景 UI 与毛玻璃文字可读） | 默认 **`1.00`**（原色全屏呈现，不压暗） | 开屏无前景遮挡，1.0 原汁原味 |
| **画面对比度** | 默认 **`1.05`** | 默认 **`1.00`** | 避免开屏动效画面过硬发脆 |
| **帧率上限** | 默认 **`60`**（可选 30 / 60 / 120 / 0 不限） | 默认 **`60`**（可选 30 / 60 / 120 / 0 不限） | **独立设置**：用户可令壁纸限 30fps 省电，但开屏 3 秒跑满 60/120fps |
| **渲染精度** | 默认 **`1.0`**（可选 0.5 / 0.75 / 1.0 / 1.25 / 1.5） | 默认 **`1.0`**（可选 0.5 / 0.75 / 1.0 / 1.25） | **独立设置**：壁纸大窗口降到 0.75x 减小显存，开屏保持 1.0x 高清呈现 |
| **自动进入首页时间** | 不适用（壁纸为桌面长驻） | **默认 `3` 秒（支持 `0 ~ 10` 秒）**<br>• `0`：停驻待机，**纯手动点击/按键进入**<br>• `1~10`：倒计时自动淡出进入 | 满足不同用户对「极速进工作区」或「驻留欣赏开机封面」的诉求 |
| **场景模式** | `dynamic` (WebGL2) 或 `static` (海报) | 暂不占用长期 WebGL，优先轻量视频/高精海报 | 开屏仅展示数秒，保障冷启动速度 |

**定位与自适应三大关键保障**：
1. **严格限定生命周期与作用域**：
   - 入口仅在设置弹窗开启、处于“设置-外观”页面、且动态壁纸/开机动画任一素材库开关开启时显示；
   - 未开设置弹窗、离开外观页（切到常规/应用/通知/模型等）、或两开关全关时，一律执行严格隐藏（`display: none`），绝不在主界面或工作区残留长驻。
2. **垂直方向智能夹紧（Vertical Viewport Clamping）**：
   - 目标锚定在外观卡片右下部（距卡片底部 22px）；
   - 当小窗口或卡片内容过多导致卡片下边缘超出设置弹窗时，算法获取宿主模态框与可滚动容器的实际可视视口 `[viewTop, viewBottom]`，将入口垂直位置动态夹紧（Clamp）在弹窗底边内衬安全线（`viewBottom - fabH`）以上，**根除悬浮入口溢出掉到弹窗外部黑灰色背景的缺陷**。

3. **水平方向防溢出自适应（Horizontal Fallback & Inner Dock）**：
   - 默认模式：左边缘贴靠大红框右边线（`card.right - 1px`，无缝融合）；

## 3. 详细技术实现方案

### 3.1 弹窗通用基础设施：`client/modules/agy-modal.js`

保持单例统一管理，挂载在 `document.body`，避免被宿主 Tailwind preflight 与局部 CSS 容器 overflow 截断：

```js
window.__agyModal = {
  ensureStyle(),                                                 // 注入遮罩与弹窗 CSS（支持深浅色变量）
  open({ id, title, subtitle, width, height, render, onClose }), // 开启弹窗并渲染
  close(id),                                                     // 关闭指定弹窗
  closeAll(),                                                    // 宿主重绘或关闭设置时批量注销
  isOpen(id),                                                    // 探活
  syncAnchor(targetEl)                                           // FAB 悬浮入口贴靠计算
};
```

**关键护栏**：
- **捕获级 ESC 拦截**：在 `document` capture 阶段拦截按键事件并阻止冒泡，避免按 ESC 时外层宿主设置弹窗一起被关闭。
- **高层级堆叠管理**：弹窗 Backdrop 为 `z-index: 5900`，Modal 为 `6000`；悬浮入口为 `5500`（高于设置主面板的 5000，但低于 Modal，弹窗开启时入口被遮罩盖住或淡出）。
- **失焦恢复**：关闭弹窗时自动把 focus 归还给唤起它的齿轮按钮。
- **视口安全区限制与智能 Clamp 锚定（`syncAnchor`）**：
  - 动态嗅探宿主 `[role="dialog"]` 与右侧内容滚动容器 `overflowY: auto`；
  - 垂直视口边界 `viewTop = modal.top + 54`（避开关闭按钮和标题），`viewBottom = min(modal.bottom - 16, window.innerHeight - 16)`（保留底边圆角安全区）；
  - 夹紧计算：`top = Math.round(max(viewTop, min(desiredTop, viewBottom - fabH)))`。即使卡片高度超过弹窗数百像素，入口始终牢固咬在弹窗底边内衬安全线以上，绝不跌落弹窗之外；
  - 水平安全约束：当 `left + fabW > modal.right - 8` 时，自动启动内嵌贴靠模式（`.agy-docked-inner`），自适应窄窗口布局；
  - 完全移出视口隐藏：当卡片被完全滚出视口或视口高度小于入口高度时，自动 `display = 'none'`，避免出现幽灵孤儿按钮。

#### 3.2.1 渲染参数的热更新管道（Wallpaper 侧）
当用户在壁纸弹窗中调节 FPS 或渲染精度时，通过以下管道**无闪烁热应用**：
1. **FPS 调节**：
   - 场景渲染器活跃时：直接调用 `window.__agySceneRenderer.setFps(fps)`（WebWallGL 原生支持运行时热调）。
   - 视频壁纸：对 `<video>` 容器无需重刷解码，落盘保存。
2. **渲染精度 (Render Scale / DPR) 调节**：
   - 场景渲染器：直接调用 `window.__agySceneRenderer.setRenderDpr(renderDpr * (window.devicePixelRatio || 1))`。
   - 立即触发 WebGL Canvas 重算 backing store 像素尺寸，画面实时变清晰或减负，无需重新 load scene.pkg。
3. **渲染模式切换（动态 WebGL vs 静态海报）**：
   - 选「静态海报」：`destroySceneRenderer()` 释放 WebGL 上下文，海报 `opacity: 1`。
   - 选「动态 WebGL」：调用 `mountSceneDynamic()` 恢复渲染。

#### 3.2.2 开屏参数管道与自动进入时序（Boot 侧）
1. **配置落盘**：将 `fit`, `fitPosition`, `brightness`, `contrast`, `fps`, `renderDpr`, `autoEnterDelay` 写入 `config.features.bootAnimationConfig` 对应字段并 `triggerSave()`。
2. **进入首页时序控制逻辑**（`boot-animation.js` 执行细节）：
   ```js
   const delaySec = Number.isFinite(bootCfg.autoEnterDelay) ? Number(bootCfg.autoEnterDelay) : 3;

   function scheduleDismiss(dismissFn) {
     if (delaySec === 0) {
       // 0 秒配置：永不自动关闭，挂载全屏点击与按键监听，界面显示提示微标
       showManualDismissHint(host);
       return;
     }
     // > 0 秒配置：准备完成后延迟 delaySec 秒自动平滑退出
     setTimeout(dismissFn, Math.max(500, delaySec * 1000));
   }
   ```
   - **当 `autoEnterDelay === 0`**：
     - 不起任何自动淡出的计时器；
     - 在画面右下角淡入微提示：`「按任意键或点击画面进入工作区」`（5 秒无操作后透明度降为 25%，不破坏画面纯净感）；
     - 点击宿主任意区域，或按下键盘 `Space` / `Enter` / `Escape`，立即触发优雅淡出，无缝唤醒主工作区与壁纸。
   - **当 `autoEnterDelay > 0`**：
     - 倒计时指定秒数后自动触发 `closeBoot()` 淡出；
     - 倒计时期间用户依然可以随时点击或按键提前跳过。
3. **现场试看**：
   - 点击开屏弹窗底部 `[▶ 立即预览]`，调用 `window.__triggerBootAnimation()`，按新设定的时长、帧率、精度进行实时推演。

```js
if (dw.sceneRenderer === 'eco') {

  if (dw.fps === undefined) dw.fps = 30;           // 解耦为 30fps

} else if (dw.sceneRenderer === 'static') {
  dw.sceneRenderer = 'static';
} else {
  dw.sceneRenderer = 'dynamic';
}

// 补齐壁纸默认值
dw.fps = Number.isFinite(dw.fps) ? dw.fps : 60;
dw.renderDpr = Number.isFinite(dw.renderDpr) ? dw.renderDpr : 1.0;

// 开屏配置独立归一化与范围 clamp
const boot = config.features.bootAnimationConfig || {};
boot.fps = Number.isFinite(boot.fps) ? boot.fps : 60;
boot.renderDpr = Number.isFinite(boot.renderDpr) ? boot.renderDpr : 1.0;
boot.autoEnterDelay = Number.isFinite(boot.autoEnterDelay)
  ? Math.min(10, Math.max(0, Math.round(boot.autoEnterDelay)))
  : 3;
```
