# 阶段十：壁纸动态交互与按键穿透引擎

> 状态：**设计就绪（待实施）**　|　版本：v0.6.0　|　前置：[阶段三](./阶段03_多形态渲染适配器与体验打磨.md)、[阶段七](./阶段07_场景动态渲染引擎（WebWallGL）.md)、[阶段八](./阶段08_参数弹窗化与素材库悬浮入口.md)

> 📌 **核心目标**：彻底打通 Wallpaper 外部素材库中 **Web 网页壁纸（HTML5/WebGL/Canvas/小游戏）** 与 **Scene 场景壁纸（WebWallGL 粒子/视差/水波）** 的点击与指针交互能力。
> 针对生产力开发环境（IDE）下“日常操作绝不能被误触打扰”与“壁纸动态可玩性”的核心矛盾，首创 **「被动视差常驻 + 按住瞬时穿透（Hold-to-Interact） + 沉浸漫游模式（Zen Mode）」** 三阶自适应交互架构。

## 1. 需求背景与痛点诊断

### 1.1 需求背景
Wallpaper Engine / WallpaperMachine 生态中，大量高质量素材具有极强的指针与点击交互属性：
- **Web 网页壁纸**：
  - 粒子重力流体（跟随鼠标聚拢、爆炸、引力场模拟）；
  - 点击互动特效（水面波纹涟漪、霓虹电弧、烟花绽放）；
  - 自带交互控件（壁纸内置的齿轮设置面板、时间/天气模式切换）；
  - 完整解压小游戏（打砖块、贪吃蛇、钢琴键、白噪音混音器等）。
- **Scene 场景壁纸**：
  - 鼠标视差相机（Parallax Depth Camera，视角随光标平移）；
  - 粒子与力场扰动（Wind / Point Force）；
  - 点击触发的微动效与木偶骨骼反应。

### 1.2 现状瓶颈与物理阻断分析
当前版本插件中，壁纸完全无法进行任何交互，根本原因存在于两层物理阻断：
1. **壁纸层自身被硬编码锁定**：
   - 在 `wallpaper.js` 中，所有形态容器（`#agy-dynamic-video`、`#agy-dynamic-iframe`、`#agy-dynamic-scene`）均被强制赋予：
     ```css
     z-index: -999999 !important;
     pointer-events: none !important;
     ```
   - 任何鼠标、触控、按键事件在 DOM 树根部即被完全忽略。
2. **宿主层级全面覆盖拦截（Host Layer Blocking）**：
   - Antigravity 基于 Electron / Web 渲染架构，顶层存在大量的全屏或大面积布局容器（工作区、编辑器、聊天记录、状态栏、毛玻璃透明底衬）。
   - 即使直接将壁纸改为 `pointer-events: auto`，由于壁纸处于 `z-index: -999999` 的最底层，宿主上方的透明 DOM 元素依然会吞噬所有鼠标事件，事件根本无法抵达底层壁纸。

### 1.3 核心冲突与“全局始终可交互”的不可行性
用户敏锐指出：“**总是能交互我觉得不太行，或者是按住某个键之后可以跟背景交互？**”

**为什么“全局常驻穿透”或“空白区域自动穿透”不可行？**
1. **严重破坏 IDE 生产力**：
   - 现代 IDE 界面包含复杂的滚动列表、聊天输入框、选中文本、代码折叠树与悬浮提示。
   - 很多视觉空白处实质是 Flexbox / Grid 布局容器的内部填充。若使用 `document.elementsFromPoint()` 暴力判定穿透，极易造成划选代码失败、拖拽滚动条失灵、点击空白区域误触发壁纸行为。
2. **焦点劫持（Focus Stealing）灾难**：
   - Web 壁纸运行在 `<iframe>` 沙箱中。一旦用户在宿主空白处点击且穿透入 iframe，窗口焦点将被立即抢夺至 iframe 内部；
   - 此时用户敲击键盘快捷键（如 `Ctrl+S`, `Cmd+P`, 输入法打字），宿主将完全无法捕获，打字中断，体验极其恶劣。
3. **GPU/CPU 算力浪费**：
   - 若光标时刻在驱动后台壁纸的物理碰撞或高精度着色器计算，在多任务编码场景下会导致不必要的发热与风扇狂转。

## 3. 技术实现细节与穿透通道

### 3.1 第 1 阶：被动坐标广播网桥（Passive Cursor Tracking）
适用于 Scene 场景壁纸的视角视差（Parallax）与 Web 壁纸的光斑跟随。

1. **机制**：
   - 在宿主 `window` 上被动捕获 `pointermove` 事件（`{ passive: true }`），完全不调用 `stopPropagation()` 或 `preventDefault()`，不对任何 IDE 操作产生阻滞。
   - 使用 `requestAnimationFrame` 进行坐标节流（锁定最高不超过壁纸配置的 `fps`，如 60fps），计算视口归一化坐标：
     $$\text{normX} = \frac{\text{clientX}}{\text{window.innerWidth}}, \quad \text{normY} = \frac{\text{clientY}}{\text{window.innerHeight}}$$
2. **分发路由**：
   - **Scene 场景轨（WebWallGL）**：
     直接调用内部 API：`sceneRendererInstance.setCursor(normX, normY)`，驱动 3D 摄像机视差与粒子扰动。
   - **Web 网页轨（iframe）**：
     通过安全的 `postMessage` 向沙箱内发送标准 Wallpaper Engine 兼容光标事件：
     ```javascript
     iframe.contentWindow.postMessage({
       type: 'wallpaperEngine:cursor',
       x: e.clientX,
       y: e.clientY,
       normX,
       normY
     }, '*');
     ```

### 3.2 第 2 阶：按住瞬时交互通道（Hold-to-Interact —— 核心主推）
这是专为“写代码累了随手解压互动”设计的黄金方案。

1. **按键捕获与生命周期**：
   - 监听全局 `keydown` 与 `keyup`：
     - **触发键**：默认 `Alt` 键（Windows）/ `Option` 键（macOS），支持在设置中自定义为 `Control` 或 `Command`。
     - 判定逻辑：仅当按住单个修饰键且当前未聚焦在输入框（若输入框内需正常输入符号则避让，但在纯按住修饰键时可直接激活）。
   - **激活态（`Alt` Down）**：
     1. 向 `<html>` 注入类名 `agy-wallpaper-interact-hold`；
     2. 壁纸容器与内部节点（iframe / canvas）的 `pointer-events` 瞬间升级为 `auto !important`，层叠上下文临时提升至穿透顶层；
     3. 宿主主工作区容器（`#workbench` / 应用主体）临时赋予 `pointer-events: none !important`；
     4. **视觉与触觉反馈**：
        - 光标变为微拟态交互指针（如带光晕的十字星或能量手势）；
        - 屏幕右上角淡入一枚极轻量的微型状态药丸：`⚡ 壁纸互动中 (松开 Alt 恢复)`；
   - **退出态（`Alt` Up / Window Blur）**：
     1. 释放 `Alt` 键或窗口失焦（`blur`）时，立即移除 `.agy-wallpaper-interact-hold`；
     2. 毫秒级恢复宿主工作区的全部 `pointer-events: auto`；
     3. **关键安全回执（焦点抢救机制）**：主动执行 `window.focus()` 并使失焦前的原宿主活动节点重新获得聚焦，彻底杜绝输入卡死。

2. **CSS 穿透原子规则**：
   ```css
   /* 瞬时穿透模式生效中 */
   html.agy-wallpaper-interact-hold {
     /* 宿主主界面整体穿透，不吃点击 */
     body > *:not(#agy-dynamic-scene):not(#agy-dynamic-iframe):not(#agy-interact-hud) {
       pointer-events: none !important;
       user-select: none !important;
     }
     /* 壁纸容器与内容接收所有指针事件 */
     #agy-dynamic-scene,
     #agy-dynamic-scene canvas,
     #agy-dynamic-iframe {
       pointer-events: auto !important;
       z-index: 999990 !important; /* 临时提升至界面上层但低于 HUD */
     }
   }
   ```

### 3.3 第 3 阶：沉浸漫游模式（Zen Interactive Mode）
适用于运行完整小游戏（如打砖块、跳跃小人）或带有复杂 UI 调节面板的网页壁纸。

1. **唤起方式**：
   - 全局快捷键：`Alt + `~`（反引号）切换；
   - 快捷入口：在「壁纸显示与渲染设置」弹窗、素材库卡片悬停菜单或 HUD 药丸上点击「进入漫游模式」按钮。
2. **交互行为与视觉动效**：
   - 宿主所有工作区面板（编辑器、侧栏、顶栏）应用平滑渐隐过度：
     ```css
     opacity: 0.04;
     filter: blur(12px);
     pointer-events: none;
     transition: all 0.4s cubic-bezier(0.16, 1, 0.3, 1);
     ```
   - 动态壁纸完全显露，满屏独占渲染；
   - 屏幕右上角常驻极具设计感的液态毛玻璃退回药丸：
     `[ 🎮 壁纸漫游模式 ｜ 按 ESC 或点击退出 ✕ ]`；
   - 按 `Escape` 键或点击退出按钮，界面以丝滑弹簧曲线恢复至 100% 正常工作台状态。

## 4. 安全沙箱与兼容层防护（Sandbox Guard）

由于 Web 壁纸来自于创意工坊等第三方网络素材，直接允许其执行与交互存在安全边界风险。必须实施严格的防线隔离：

| 防御维度 | 防护策略 | 实现方案 |
| :--- | :--- | :--- |
| **路由劫持拦截** | 严禁壁纸跳转宿主应用 URL | `<iframe>` 严格保持 `sandbox="allow-scripts allow-same-origin allow-pointer-lock"`，**严禁添加 `allow-top-navigation`** |
| **弹窗与打扰拦截** | 严禁壁纸弹出 alert / confirm | 沙箱中禁止 `allow-modals`，屏蔽页面级模态弹窗 |
| **输入法与全角冲突** | 避免 Alt 键与系统快捷键冲突 | 允许用户在设置中自定义修饰键（`Alt`, `Shift`, `Control`, `None`） |
| **快捷键冲突守卫** | `Esc` 键冲突处理 | 当宿主已有打开的 Modal 弹窗时，`Esc` 优先关闭上层 Modal；仅当无 Modal 处于 Zen 漫游模式时才用于退出漫游 |

## 6. 里程碑交付计划与验收标准

### 6.1 里程碑拆解
1. **M1：底层穿透样式与事件网桥打通**
   - 在 `wallpaper.js` 中构建交互管理器，支持类名挂载与 `pointer-events` 动态切换；
   - 接入 rAF 坐标被动转发引擎，完成 WebWallGL 与 iframe 光标联动。
2. **M2：Hold 按住瞬透机制落地**
   - 监听修饰键按下/抬起，增加屏幕 HUD 提示与光标反馈；
   - 实现失去焦点与松键时的焦点自动找回保底。
3. **M3：Zen 沉浸漫游模式与 Esc 退出链**
   - 实现工作区 UI 平滑渐隐淡出动效；
   - 增加右上角悬浮退出玻璃胶囊与 `Esc` 键监听。
4. **M4：外观设置弹窗参数集成与文档归档**
   - 在阶段八弹窗中集成开关与修饰键选择下拉；
   - 编写多款典型 Web/Scene 壁纸（流体粒子、水波、网页小游戏）的实测用例。

### 6.2 交付验收标准
- [ ] **日常打字零干扰**：普通状态下，编辑器、聊天区的所有点击、划词、滚动 100% 正常，无任何误穿透。
- [ ] **按住 Alt 随手互动**：按住 `Alt` 键，点击 Web 粒子壁纸能立即产生物理涟漪；松开 `Alt`，1 毫秒内恢复 IDE 输入，焦点不丢失。
- [ ] **沉浸漫游完整游玩**：按 `Alt+`~` 进入漫游模式，全屏可完整操控网页壁纸（含小游戏点击与拖动），按 `Esc` 完美平滑退回。
- [ ] **CPU/GPU 负载受控**：未按键时后台不产生额外的点击捕获开销，视差计算严格受制于 rAF 节流。
