# Wallpaper Engine / WallpaperMachine 外部素材库集成总计划

## 1. 需求背景与核心目标

### 1.1 需求背景
用户在 macOS 上使用开源壁纸软件 **WallpaperMachine**（兼容 Steam 创意工坊 Wallpaper Engine 壁纸库），本地存在已下载的壁纸目录（如样例：`/Users/colorh/Library/Application Support/WallpaperMachine/Library/3812610550`）。
目前 Antigravity 换肤插件（`antigravity-skin`）仅支持导入内置的视频和脚本，且导入时会将数十兆甚至数百兆的文件拷贝到插件自身目录中，导致磁盘空间大量冗余占用，且无法直接使用 Wallpaper 库中海量丰富的动态壁纸与开机动效。

### 1.2 核心目标
1. **零数据拷贝（Zero-Copy 原地引用）**：
   - 严禁将外部素材复制到反重力本地插件目录；
   - 建立绝对路径原地引用索引，通过本地 Sidecar 流媒体代理直接伺服。
2. **多形态壁纸格式支持**：
   - 支持 `video`（视频壁纸，MP4 / WebM）；
   - 支持 `web`（HTML5 / JS / WebGL 网页壁纸）；
   - 支持 `scene`（场景壁纸，以高质量预览图、解包音视频或桌面穿透形式呈现）；
   - **严格过滤排除 `application`（exe 可执行文件）**。
3. **双模式灵活载入**：
   - **单壁纸目录载入**：用户直接选中某个具体壁纸文件夹（如 `3812610550`），解析 `project.json` 即刻挂载；
   - **Library 根目录扫描**：用户指定或选择素材库根目录（如 `~/Library/Application Support/WallpaperMachine/Library`），自动全量扫描与持久化挂载。
4. **壁纸与开屏动画双向打通**：
   - 统一资产中心，外部素材库中的素材既可一键设为**动态壁纸**，也可一键设为**开屏动画**。

## 2. 系统技术架构设计

```
┌───────────────────────────────────────────────────────────────┐
│                 外部壁纸素材库 (零拷贝原地引用)               │
│   • 单壁纸目录 (如 3812610550 / 3400422354)                  │
│   • 或 Library 根目录 (~/.../WallpaperMachine/Library)        │
└───────────────────────────────┬───────────────────────────────┘
                                │ 绝对路径引用 (写入 config.json)
                                ▼
┌───────────────────────────────────────────────────────────────┐
│              Sidecar 后端引擎 (Node.js :59288)                │
│   • 目录与清单解析器 (project.json 解析 / 排除 exe)           │
│   • 根目录递归扫描器 (批量提取 Title, Preview, Type, File)    │
│   • 零拷贝 HTTP 流代理 (/api/video, /wallpaper.mp4, Range 206)│
│   • 静态资源与预览图代理 (/api/wallpaper-library/preview)     │
│   • Web 壁纸静态托管 (/api/wallpaper-library/web/*)           │
└───────────────────────────────┬───────────────────────────────┘
                                │ 内部 Localhost HTTP & WS
                                ▼
┌───────────────────────────────────────────────────────────────┐
│              Antigravity 前端渲染层 (Electron)                │
│   ├── 外观设置菜单 (Appearance Menu)                          │
│   │   ├── 外部库路径设置 / 目录选择器                         │
│   │   ├── 资产网格列表 (封面图 + 标题 + 类型角标)             │
│   │   └── 快捷动作：[设为动态壁纸] / [设为开屏动画]          │
│   ├── 动态壁纸渲染器 (Dynamic Wallpaper Engine)               │
│   │   ├── <video> 硬件加速层                                  │
│   │   ├── <iframe> 网页壁纸沙箱容器                           │
│   │   └── 场景壁纸高品质海报 / Ken Burns 动效容器             │
│   └── 开屏动画引擎 (Boot Animation Engine)                    │
│       └── 继承外部视频/动效，启动即播，无缝淡入工作区         │
└───────────────────────────────────────────────────────────────┘
```

## 3. 壁纸格式技术矩阵与适配规范

| 类型 (`type`) | 典型标识 | 处理机制 | 动态壁纸适配 | 开屏动画适配 |
| :--- | :--- | :--- | :---: | :---: |
| **`video`** | `file: "*.mp4"` 等 | 本地 HTTP Range 分块流直接喂给原生 `<video>` 元素 | 原生硬件加速播放 | 支持作为开机短视频 |
| **`web`** | `file: "index.html"` | Sidecar 静态目录安全托管 + 无边框全屏 `<iframe>` 嵌入 | 交互式网页壁纸 | 优雅淡入展示 |
| **`scene`** | `scene.pkg` / `scene.json` | 提取高质量原画封面与动态预览图，配合微动效与毛玻璃；提取内嵌背景音乐 | 沉浸式海报壁纸 | 高清海报动效 |
| **`application`** | `file: "*.exe"` | **严格拦截与排除**：扫描时自动跳过，禁止运行与载入 | ❌ 明确不支持 | ❌ 明确不支持 |

## 4. 阶段拆分与里程碑规划

本需求划分为以下三个递进阶段，每个阶段均包含详细的技术设计与交付验证标准：

* **[阶段一：核心引擎与零拷贝后端管道](./阶段一-核心引擎与零拷贝后端管道.md)**
  - 核心职责：目录扫描、`project.json` 解析、外部流代理、预览图直读、安全过滤。
  - 交付产物：稳定高效的 Node.js Sidecar API 接口与零拷贝路径解析器。
* **[阶段二：前端资产中心与外观菜单改造](./阶段二-前端资产中心与外观菜单改造.md)**
  - 核心职责：设置面板 UI、根目录与单目录载入交互、统一资产卡片、一键设为壁纸/开机动画。
  - 交付产物：所见即所得的可视化管理界面与双向配置联动。
* **[阶段三：多形态渲染适配器与体验打磨](./阶段三-多形态渲染适配器与体验打磨.md)**
  - 核心职责：Iframe 网页壁纸容器、Scene 场景壁纸多级渲染降噪、开机与主界面的无缝平滑切换、性能与内存优化。
  - 交付产物：高流畅度、全格式兼容且低功耗的生产力级视觉换肤体验。
