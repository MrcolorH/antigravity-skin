# Wallpaper Engine / WallpaperMachine 外部素材库集成总计划

## 1. 需求背景与核心目标

### 1.1 需求背景
用户在 macOS 上使用开源壁纸软件 **WallpaperMachine**（兼容 Steam 创意工坊 Wallpaper Engine 壁纸库），本地存在已下载的壁纸目录（如样例：`/Users/colorh/Library/Application Support/WallpaperMachine/Library/3812610550`）。
目前 Antigravity 换肤插件（`antigravity-skin`）仅支持导入内置的视频和脚本，且导入时会将数十兆甚至数百兆的文件拷贝到插件自身目录中，导致磁盘空间大量冗余占用，且无法直接使用 Wallpaper 库中海量丰富的动态壁纸与开机动效。

### 1.2 核心目标
1. **零数据拷贝（Zero-Copy 原地引用）**：
   - 严禁将外部素材复制到反重力本地插件目录；
   - 建立绝对路径原地引用索引，通过本地 Sidecar 流媒体代理直接伺服。
2. **多形态壁纸格式支持**：
   - 支持 `video`（视频壁纸，MP4 / WebM）；
   - 支持 `web`（HTML5 / JS / WebGL 网页壁纸）；
   - 支持 `scene`（场景壁纸，以高质量预览图、解包音视频或桌面穿透形式呈现）；
   - **严格过滤排除 `application`（exe 可执行文件）**。
3. **双模式灵活载入**：
   - **单壁纸目录载入**：用户直接选中某个具体壁纸文件夹（如 `3812610550`），解析 `project.json` 即刻挂载；
   - **Library 根目录扫描**：用户指定或选择素材库根目录（如 `~/Library/Application Support/WallpaperMachine/Library`），自动全量扫描与持久化挂载。
4. **壁纸与开屏动画双向打通**：
   - 统一资产中心，外部素材库中的素材既可一键设为**动态壁纸**，也可一键设为**开屏动画**。

## 2. 系统技术架构设计

```
┌───────────────────────────────────────────────────────────────┐
│                 外部壁纸素材库 (零拷贝原地引用)               │

│   • 或 Library 根目录 (~/.../WallpaperMachine/Library)        │
└───────────────────────────────┬───────────────────────────────┘
                                │ 绝对路径引用 (写入 config.json)
                                ▼
┌───────────────────────────────────────────────────────────────┐

│   • 根目录递归扫描器 (批量提取 Title, Preview, Type, File)    │
│   • 零拷贝 HTTP 流代理 (/api/video, /wallpaper.mp4, Range 206)│
│   • 静态资源与预览图代理 (/api/wallpaper-library/preview)     │
│   • Web 壁纸静态托管 (/api/wallpaper-library/web/*)           │
└───────────────────────────────┬───────────────────────────────┘
                                │ 内部 Localhost HTTP & WS
                                ▼
┌───────────────────────────────────────────────────────────────┐

│   ├── 外观设置菜单 (Appearance Menu)                          │

│   │   ├── 资产网格列表 (封面图 + 标题 + 类型角标)             │
│   │   └── 快捷动作：[设为动态壁纸] / [设为开屏动画]          │
│   ├── 动态壁纸渲染器 (Dynamic Wallpaper Engine)               │
│   │   ├── <video> 硬件加速层                                  │
│   │   ├── <iframe> 网页壁纸沙箱容器                           │
│   │   └── 场景壁纸高品质海报 / Ken Burns 动效容器             │
│   └── 开屏动画引擎 (Boot Animation Engine)                    │
│       └── 继承外部视频/动效，启动即播，无缝淡入工作区         │
└───────────────────────────────────────────────────────────────┘
```

## 3. 壁纸格式技术矩阵与适配规范

| 类型 (`type`) | 典型标识 | 处理机制 | 动态壁纸适配 | 开屏动画适配 |
| :--- | :--- | :--- | :---: | :---: |
| **`video`** | `file: "*.mp4"` 等 | 本地 HTTP Range 分块流直接喂给原生 `<video>` 元素 | 原生硬件加速播放 | 支持作为开机短视频 |
| **`web`** | `file: "index.html"` | Sidecar 静态目录安全托管 + 无边框全屏 `<iframe>` 嵌入 | 交互式网页壁纸 | 优雅淡入展示 |
| **`scene`** | `scene.pkg` / `scene.json` | 提取高质量原画封面与动态预览图，配合微动效与毛玻璃；提取内嵌背景音乐 | 沉浸式海报壁纸 | 高清海报动效 |
| **`application`** | `file: "*.exe"` | **严格拦截与排除**：扫描时自动跳过，禁止运行与载入 | ❌ 明确不支持 | ❌ 明确不支持 |

## 4. 阶段拆分与里程碑规划

本需求划分为以下递进阶段，每个阶段均包含详细的技术设计与交付验证标准：

* **[阶段01：核心引擎与零拷贝后端管道](./阶段01_核心引擎与零拷贝后端管道.md)** ✅ 已落地
  - 核心职责：目录扫描、project.json 解析、外部流代理、预览图直读、安全过滤。
  - 交付产物：稳定高效的 Node.js Sidecar API 接口与零拷贝路径解析器。
* **[阶段02：前端资产中心与外观菜单改造](./阶段02_前端资产中心与外观菜单改造.md)** ✅ 已落地
  - 核心职责：设置面板 UI、根目录与单目录载入交互、统一资产卡片、一键设为壁纸/开机动画。
  - 交付产物：所见即所得的可视化管理界面与双向配置联动。
* **[阶段03：多形态渲染适配器与体验打磨](./阶段03_多形态渲染适配器与体验打磨.md)** ✅ 已落地（桌面透射待宿主能力）
  - 核心职责：Iframe 网页壁纸容器、Scene 场景壁纸多级渲染降噪、开机与主界面的无缝平滑切换、性能与内存优化。
  - 交付产物：高流畅度、全格式兼容且低功耗的生产力级视觉换肤体验。
* **[阶段04：双开关交互重构与年龄分级筛选](./阶段04_双开关交互与分级筛选.md)** ✅ 已落地（v0.2.0）
  - 核心职责：动态壁纸 / 开屏动画各自独立的素材库开关；库模式下隐藏原生载入区并改为「使用中」标识；素材库区块下移至在线更新之后；卡片选中态按动作配色（蓝 / 绿 / 渐变）；对齐 WallpaperMachine 的 Everyone / Questionable / Mature 分级筛选。
  - 交付产物：双通道互不干扰的素材来源模型 + 可解释的分级可见性控制。
  - ⚠️ 本阶段**取代**实现记录 §2.0 的单开关模型，冲突处以阶段四为准。
* **[阶段05：展陈几何与无黑边适配](./阶段05_展陈几何与无黑边适配.md)** ✅ 已落地（v0.3.0）
  - 核心职责：定位「视频无法铺满 / 与窗口不匹配」根因，建立统一几何控制器与 cover / blur / contain / fill 四种展陈策略。
* **[阶段07：场景动态渲染引擎（WebWallGL）](./阶段07_场景动态渲染引擎（WebWallGL）.md)** ⚙️ 已实施待收尾（预计 v0.5.0)
  - 核心职责：集成 WebWallGL WebGL2 渲染核心，将静态海报升级为完整动态图层视差、粒子、着色器、木偶骨骼装配；提供静态海报兜底。
* **[阶段08：参数弹窗化、精细渲染控制与素材库悬浮入口](./阶段08_参数弹窗化与素材库悬浮入口.md)** ✅ 已落地（v0.5.0）
  - 核心职责：壁纸/开屏分别提供独立的显示与渲染设置弹窗（「使用中」胶囊升级为齿轮按钮），覆盖铺满方式、亮度/对比度独立的渲染帧率 (FPS) 与渲染精度 (Render Scale / DPR)，以及开屏自动进入首页时间 (0~10s，0为纯手动进入)；彻底剔除阶段七内联的粗粒度三档调节下拉并平滑迁移；素材库资产中心迁入独立弹窗。
  - 交付产物：主设置面板精简紧凑 + 壁纸与开屏分别拥有独立的性能调优与调色管道 + 素材库成为按需唤起的独立工作台。
* **[阶段08a：素材库入口由悬浮回归框内集成方案](./阶段08a_素材库入口由悬浮回归框内集成方案.md)** ✅ 已落地（v0.5.0 修订）
  - 核心职责：彻底根除全局悬浮 DOM 计算开销，将素材库入口回归在设置弹窗框内右上角流式内嵌，实现零自激与整洁布局。
* **[阶段09：页面闪烁与动图渲染抖动修复](./阶段09_页面闪烁与动图渲染抖动修复.md)** ✅ 已落地（v0.5.1）
  - 核心职责：消除加载场景壁纸时的连闪与黑屏抽搐（海报双缓冲预加载 + 550ms 延迟淡出 Cross-fade）；通过离屏 Canvas 冻结素材库工坊 GIF 动图首帧覆盖，支持 Hover 平滑试看；修复外观菜单 Mutation 自激死循环（突变率从 629次 归零）；优化素材库弹窗为单层原生标题栏并整合刷新动作。
  - 交付产物：零黑闪场景切换体验 + 素材库宁静优雅浏览质感 + 宿主 DOM 性能零自激抖动。
* **[阶段10：壁纸动态交互与按键穿透引擎](./阶段10_壁纸动态交互与按键穿透引擎.md)** 📋 设计就绪（规划 v0.6.0）
  - 核心职责：打通 Web 网页壁纸与 Scene 场景壁纸的点击与指针交互能力；建立「常驻被动视差广播 + 按住修饰键（Alt/Option）瞬时穿透（Hold-to-Interact） + 沉浸漫游模式（Zen Mode）」三阶正交架构；配合防焦点劫持保护与安全沙箱，兼顾日常生产力编码的绝对零误触与高玩壁纸的沉浸乐趣。
  - 交付产物：零干扰 IDE 日常操作 + 随时按住 Alt 解压互动 + Alt+ 沉浸畅玩小游戏与调参。
* **[阶段11：场景壁纸原子性呈现与无缝换轨引擎（参考WallpaperMachine）](./阶段11_场景壁纸原子性呈现与无缝换轨引擎（参考WallpaperMachine）.md)** ⚙️ 实施中（预计 v0.6.0）
  - 核心职责：参考 WallpaperMachine 官方 C++ 源码（VFS 虚拟文件系统与原子性渲染），彻底废除动态模式下的单层半成品海报曝光；显式注入 `fade: false` 掐灭场景自带相机黑屏淡入；建立开屏遮罩幕后 1200ms 深度暖机机制与双缓冲原子性交接。
  - 交付产物：彻底消除多图层场景冷启动与切换时的“空背景”与“黑屏”断层，揭开幕布直接呈现 4K 原生动态成型画面。
