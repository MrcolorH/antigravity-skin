# 子模块五：壁纸交互穿透与按键响应系统 (Wallpaper Interaction & Key Pierce Engine)

> **模块状态**：`已完成并归档 (v0.2.0)`  
> **核心定位**：解决 Antigravity 插件中壁纸“看得见摸不着”、无法进行任何鼠标点击与动态交互的痛点。通过**「按住自定义键穿透（Hold-to-Interact）」**创新机制，在确保日常代码编写、界面操作 100% 零误触的前提下，完美释放 Wallpaper 外部壁纸的点击响应（如点击左右切换人物、触发特效、玩解压小游戏等）。  
> **归档实现记录**：[子模块五实现记录](./实现记录.md)

---

## 一、 需求痛点与设计原则

1. **痛点：壁纸被宿主界面物理阻断**
   - 当前壁纸容器（`#agy-dynamic-scene`、`#agy-dynamic-iframe`）被全局硬编码赋予 `pointer-events: none` 且 `z-index: -999999`；
   - 宿主（Antigravity / VS Code）上层覆盖着编辑器、侧边栏、透明底衬等大量 DOM 节点；
   - 用户无法与壁纸发生任何鼠标点击交互（如切换角色立绘、点击开关音乐、玩 Web 网页壁纸等）。

2. **原则：生产力环境绝不能“常驻盲穿”**
   - IDE 编码场景下，空白处常常是编辑器或列表的填充区。若开启全局常驻穿透，会导致代码选中文本失败、拖动滚动条失灵、点击空白处误抢焦点；
   - 因此，**“按住某个键才临时激活穿透，松开瞬间恢复 IDE”** 是兼顾工作效率与壁纸可玩性的最优解。

3. **典型场景：点击左右切换角色**
   - 在 Wallpaper Engine 场景壁纸（Scene 类型）中，许多角色壁纸包含 SceneScript 点击逻辑（例如：检测光标点击屏幕左侧或右侧区域，切换人物立绘图层或换装）；
   - 必须确保鼠标点击与坐标能够精准传导至底层渲染引擎（WebWallGL / Iframe）。

## 三、 模块交付产出物清单

1. **按键瞬时穿透引擎（Hold-to-Interact）**：按住指定键（默认 Alt）即可直达壁纸，松手毫秒级复原；
2. **多形态壁纸事件通道**：
   - **Scene 场景壁纸**：支持 SceneScript 鼠标点击、光标位移、左右切换人物；
   - **Web 网页壁纸**：支持 iframe 原生交互、DOM 按钮点击、解压小游戏；
3. **零失焦安全防线**：失焦强制退出穿透、松手主动拉回宿主焦点，杜绝键盘输入卡死；
4. **外观设置弹窗集成**：支持用户自由选择触发键（`Alt`, `Shift`, `Control`, `Meta`）；
5. **极简微态 HUD 胶囊**：按住时右上角优雅提示交互状态，松开无痕消失。
