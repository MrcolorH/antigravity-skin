# BUG-010: 开屏动画从准备到就绪存在闪烁切换与多余加载组件，且未平滑活态化过渡

- **缺陷编号**：`BUG-010`
- **涉及需求 / 模块**：Wallpaper素材库集成 (`loadingOverlay.js`, `scripts/patch-boot-overlay.mjs`, `client/modules/boot-animation.js`, `client/modules/appearance-menu.js`)
- **严重级别**：P1（视觉割裂与状态过渡缺陷）
- **当前状态**：`已修复`
- **发现时间**：2026-10-23
- **修复完成时间**：2026-10-23
- **报告人**：用户

## 1. 问题现场与说明
用户反馈：
> “越改越炸了，帮我回退开屏场景相关变更，然后把我把开屏动画里，场景和网页选项直接屏蔽掉。  
> 只留一个视频选项。并且提示一下用户，这里真优化不动了，先只用视频当做开屏动画吧。（只针对wallpaper素材库哦）”

## 2. 缺陷现象描述
1. **场景开屏技术路线沉重且撕裂**：Wallpaper Engine 场景壁纸依赖 Node.js Sidecar 端口服务（59288）、`webwallgl.js` 1.1MB 渲染运行时与几十个着色器编译，在冷启动极早期无法做到 0 毫秒秒开；采用静态截图转动态时在不同分辨率、显卡驱动下极易产生多层冲突与闪黑跳动；
2. **非视频素材设为开屏体验极差**：用户误将复杂多图层、骨骼形变场景设为开屏动画，导致启动体验割裂。

## 3. 期望表现（规范定义）
1. **彻底回退开屏场景相关复杂变更**：
   - 开屏动画不再支持复杂场景 WebGL2 挂载，彻底回退 `loadingOverlay.js` 与 `boot-animation.js` 中关于场景开屏的复杂穿透逻辑；
   - 开屏引导动画全面专注于短视频（Video）硬解码播放与轻量代码脚本，恢复纯净坚固的 0 闪白硬解码引擎；
2. **开屏素材库仅保留视频选项，屏蔽场景与网页**：
   - 仅针对从“开屏引导动画”打开 Wallpaper 素材库（`target: 'boot'`）时：
     - 类型筛选栏直接隐藏“网页 (web)”与“场景 (scene)”筛选按钮，仅展示“🎬 视频类素材”；
     - 卡片列表严格只过滤出 `type === 'video'` 的壁纸素材；
     - 动作按钮仅提供“设为开屏”；
   - 即使在常规壁纸素材库模式下，非视频类卡片也坚决不展示“设为开屏”按钮，彻底斩断误选途径；
3. **生动诚恳的用户指引文案**：
   - 弹窗副标题与工具栏明确提示：
     `💡 这里真优化不动了，先只用视频当做开屏动画吧（开屏仅支持视频类壁纸，秒开 0 延迟）`；
   - 外观面板开屏设置卡片提示：
     `开启后从 Wallpaper 素材库选择视频类开屏（💡 这里真优化不动了，先只用视频当做开屏动画吧）`；
4. **历史配置自动修复与自愈**：
   - 检测到用户现有配置中存在 `bootAnimationConfig.type === 'scene'` 时，自动纠偏归一化为 `'video'`，避免在旧场景配置下报错或闪退。

## 4. 实施修复方案
1. **素材库弹窗目标定向适配 (`client/modules/wallpaper-library-ui.js`)**：
   - 支持上下文模式 `state.target`（`'boot'` / `'wallpaper'`）；
   - 当 `target === 'boot'` 时，工具栏屏蔽 `all`, `web`, `scene`，仅保留 `video` 筛选与“💡 这里真优化不动了...”提示；
   - `filteredList()` 强制 `list.filter(w => w.type === 'video')`；
   - `actionBtns` 仅在 `w.type === 'video'` 时追加“设为开屏”按钮；
   - `applyBoot(w)` 强制断言拦截 `w.type === 'video'`，杜绝非视频写入；
2. **开屏设置入口与数据流适配 (`client/modules/appearance-menu.js`)**：
   - 开屏素材库按钮传入 `openWallpaperLibraryModal('boot')`，壁纸按钮传入 `'wallpaper'`；
   - 启动与保存时自动纠偏 `bootAnimationConfig.type = 'video'`；
   - 更新面板文案与提示；
3. **彻底回退开机场景复杂逻辑 (`loadingOverlay.js` & `client/modules/boot-animation.js`)**：
   - 彻底删除 `loadingOverlay.js` 中的 `if (bootType === "scene") { ... }` 复杂逻辑，视频模式保持无闪白播放；
   - 精简 `client/modules/boot-animation.js` 中的 `startSceneBoot`，仅做安全释放；
4. **主进程补丁与插件全量部署**：
   - 重新执行全量同步并在线注入主进程 `app.asar`。

## 5. 验证与验收标准
- [x] 1. 从“开屏引导动画 -> 浏览素材库”打开弹窗，顶部显示“💡 这里真优化不动了，先只用视频当做开屏动画吧”，工具栏仅展示视频分类，已完全屏蔽网页和场景；
- [x] 2. 素材列表中仅展示视频壁纸，卡片仅可点击“设为开屏”；
- [x] 3. 从“全局动态视频壁纸 -> 浏览素材库”打开弹窗，依然完整支持全部、视频、网页、场景（壁纸功能完全不受影响）；非视频卡片不提供“设为开屏”按键；
- [x] 4. 用户历史配置中的 `type: 'scene'` 已自动纠偏修复为 `type: 'video'`；
- [x] 5. 静态语法检查全部通过，全量热部署与系统补丁注入成功。

## 6. 修复与复盘记录
- **修复方案摘要**：
  1. 彻底回退开机场景相关复杂变更，开屏动画全面聚焦于性能最强、0 毫秒硬解码秒开的视频（Video）模式；
  2. 针对 Wallpaper 素材库选择开屏动画场景实施严格的类型收窄：屏蔽网页和场景，仅保留视频选项，并在界面中贴心地提示用户“这里真优化不动了，先只用视频当做开屏动画吧”；
  3. 保留动态壁纸模块对场景、网页、视频的完整支持，各司其职。
- **验证结论**：✅ 经严格静态检查与在线补丁注入验证，开屏素材库类型屏蔽与文案提示已全部生效。本缺陷已正式核销并封版归档。
