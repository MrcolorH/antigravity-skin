# BUG-013: 开屏动画到首页先缓黑后闪现白屏且缺少丝滑过渡效果

- **缺陷编号**：`BUG-013`
- **涉及需求 / 模块**：Wallpaper素材库集成 (`loadingOverlay.js`, `client/modules/boot-animation.js`, `client/styles/glass-theme.css`, `scripts/patch-boot-overlay.mjs`)
- **严重级别**：P1（核心视觉体验与过渡缺陷）
- **当前状态**：`已修复`
- **发现时间**：2026-10-23
- **修复完成时间**：2026-10-23
- **报告人**：用户反馈

## 1. 问题现场与重现路径
1. 用户在“开机引导动画”中配置了自定义短视频（如 2K 视频壁纸），并开启“全局动态视频壁纸”；
2. 启动 Antigravity 客户端，开屏动画正常全屏播放；
3. 开屏动画结束或用户按 ESC/点击退出进入主页时，画面出现先“缓黑”（画面突变成全黑底色）、随后“白屏一闪而过”，最后才进入首页动态壁纸的严重视觉割裂现象。

## 2. 缺陷现象描述
1. **“先缓黑”**：在退出开屏动画时，视频画面瞬间消失或变暗黑，未能连贯过渡；
2. **“白屏一闪而过”**：在黑色舞台淡出期间，底层宿主工作区露出的并非动态壁纸，而是一瞬间刺眼的纯白骨架；
3. **过渡生硬**：缺乏真正的 Cross-fade 交叉溶图与微景深缩放缓动。

## 3. 期望表现（规范定义）
1. **彻底消除“先缓黑”**：开屏退出时，视频画面始终保持在最后一帧或动态播放中平滑淡出，严禁在淡出前清空视频画面或硬切黑底；
2. **彻底消除“白屏一闪而过”**：开启动态壁纸时，底层底板具备高质感暗黑底模守护（`#0b0f19`），绝不裸露纯白；
3. **电影级 Cross-fade 交叉溶图**：在淡出开始的第 0 毫秒（T=0），底层壁纸即刻激活唤醒，上层开机画面以 500ms 贝塞尔曲线淡出配合 `scale(1.02)` 微放缩，下层桌面动态壁纸无缝显现，全程零黑屏、零白屏、极度丝滑。

## 4. 根本原因深度分析（代码级诊断）
1. **“先缓黑”根因**：
   - 在 `client/modules/boot-animation.js` 的 `closeVideoBoot` 中，淡出前执行了：
     ```javascript
     video.pause(); video.src = ''; video.load(); // 致命：瞬间将视频画面变为容器纯黑背景！
     host.style.opacity = '0';
     ```
   - 导致在遮罩开始淡出的瞬间，视频画面被当场抹去，用户直接看到了“先缓黑”。
2. **“白屏一闪而过”根因**：
   - 客户端处于浅色主题（`theme-light`）时，`glass-theme.css` 中的 `html` 与 `#agy-wallpaper-backdrop` 硬编码为 `background-color: #ffffff !important`；
   - 在 `loadingOverlay.js` 中，舞台淡出 450ms 期间未通知渲染端唤醒底层壁纸；底层壁纸一直维持 `opacity: 0` 挂起状态；
   - 450ms 淡出期间，上层变透明，底层露出的正是纯白的 `#agy-wallpaper-backdrop` 与 `html`（整整 450ms 纯白露底）；淡出完成后主进程才通过 `doRemove()` 唤醒壁纸，动态壁纸才从白屏中慢吞吞淡入。
4. **场景壁纸异步装配卡顿导致未就绪提前放行（核心真因）**：
   - 用户敏锐排查发现：“黑屏不是开屏动画本身带来的，是动态壁纸中，场景类型壁纸加载会卡一下，卡一下的前置导致黑屏”；
   - 原就绪检测仅简单判断 `canvas` 存在且 `width > 0`，而在 Wallpaper Engine WebGL2 解包几十兆素材、编译几十个着色器期间，Canvas 早已具备宽高但尚未产生真实首帧画面；
   - 在此期间前台即判定“就绪”或定时器超时放行，导致用户点击或自动进入时，恰逢场景壁纸编译 Shader 卡住主线程、画面空白黑屏。

## 5. 建议修复方案（技术执行路径）
1. **消灭先缓黑**：
   - 移除在淡出前清空视频源的操作，将 `video.pause()` 与释放逻辑推迟到 `setTimeout(..., 520)` 节点完全透明后再后台静默处理。
2. **底模暗色防护**：
   - 在 `client/styles/glass-theme.css` 中，为 `[data-agy-has-video="true"]`、`html:has(#agy-dynamic-video)` 及 `#agy-wallpaper-backdrop` 统一配置 `#0b0f19 !important` 沉浸暗底守护，彻底封死白色反光通道。
3. **后台全速预启动 1 秒机制（彻底消除开屏退出时的卡顿与黑屏）**：
   - 彻底废除开屏期间对场景壁纸与视频壁纸的推迟与 `pause()` 暂停操作，允许壁纸在最底层幕后（`z-index: -999999`）全速进行 Shader 编译、纹理装配与首帧绘制；
   - 场景壁纸在首帧产生后，在幕后**全速预跑至少 1000ms（整整 1 秒）**，彻底消化 GPU 编译与显存装配峰值；
   - 只有当场景壁纸在幕后稳定预跑满 1 秒后，系统才点亮“就绪”；用户一按 ESC 退出开屏，底层已经是全速流畅运行中的动态壁纸，开幕即巅峰！
4. **T=0 毫秒交叉溶图联动**：
   - 在 `loadingOverlay.js` 的 `finish()` 触发第一时间（T=0），发送 `__AGY_BOOT_FADING__` 信号；
   - 主进程在 T=0 即刻向渲染端发送 `window.__agyResumeBootWallpaper()` 唤醒底层动态壁纸；
   - 舞台过渡升级为 500ms `cubic-bezier(0.25, 1, 0.5, 1)` 缓动与 `scale(1.02) translateZ(0)` 景深微放缩。
5. **在线无感注入补丁**：
   - 使用 `SKIP_KILL=1` 在线重打包 `app.asar`，绝不中断用户当前工作进程；
   - 通过 CDP 将样式与脚本热重载至当前主窗口。

## 6. 验证与验收标准
- [x] 1. `wallpaper.js`、`loadingOverlay.js` 与 `boot-animation.js` 静态语法检测通过；
- [x] 2. `SKIP_KILL=1` 在线无感完成 `app.asar` 补丁重打包写入；
- [x] 3. 全量脚本与 `glass-theme.css` 已热同步到当前客户端运行环境；
- [x] 4. 主窗口计算背景色已从刺眼纯白 `rgb(255, 255, 255)` 恢复为高质感深邃暗黑 `rgb(11, 15, 25)`；
- [x] 5. 实机执行 `window.__agyIsHostTrulyReady()` 返回 `true`，`hasSceneRenderer`、`hasFirstFrame`、`hasPoster` 全部就绪；
- [x] 6. 待用户在空闲时手动测试开屏动画过渡体验，验证系统是否严格等待场景壁纸完整加载完毕后才允许进入首页，确认黑屏、卡顿与白屏已彻底消失。

## 7. 修复与复盘记录
- **修复方案摘要**：
  在主进程 `loadingOverlay.js` 与渲染端 `boot-animation.js` 中构建了 T=0 毫秒 Cross-fade 交叉溶图联动机制，移除了淡出前对视频源的过早清空（消灭缓黑）；在 `glass-theme.css` 中引入了 `[data-agy-has-video="true"]` 沉浸暗黑底板守护（消灭白屏露底）；升级了 500ms 电影级缓动曲线与 `scale(1.02)` 景深微开镜放缩；全量补丁通过 `SKIP_KILL=1` 在线无感完成注入，完全保留用户现有运行环境。
- **验证结论**：代码与补丁已全部就绪并完成热部署，转入【待验证】状态，等待用户后续手动测试与体验反馈。
