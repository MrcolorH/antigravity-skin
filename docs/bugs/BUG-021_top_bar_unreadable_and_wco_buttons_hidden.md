# BUG-021: 顶部文字黑压黑几乎不可读 + 原生最小化/最大化/关闭按钮整体消失

- **缺陷编号**：`BUG-021`
- **涉及需求 / 模块**：Wallpaper 素材库集成 / 毛玻璃主题 · 顶部标题栏与 WCO 窗口控制
- **严重级别**：P0
- **当前状态**：`已修复`
- **发现时间**：2026-10-25
- **修复完成时间**：2026-10-25
- **报告人**：用户实机反馈

## 1. 问题现场

| 环境 | 原生主题 | 壁纸 | 顶部条带实测色 |
| :--- | :--- | :--- | :--- |
| Windows 11 · Antigravity 2.26.0 | 浅色（`--background:#F9F9F9`） | `earth` 网页壁纸（`sourceType: web`） | RGB ≈ **(8, 18, 27)**，相对亮度 **0.0063** |

- 顶部菜单（Antigravity / 文件 / 视图 / 窗口）实测字色 `rgb(0,0,0)`，压在亮度 0.006 的近黑壁纸上 → 对比度 ≈ 1.1:1，肉眼几乎完全看不见；
- 右上角最小化 / 最大化 / 关闭按钮**完全没有渲染**：`navigator.windowControlsOverlay.visible === false`；
- 部分页面（Overview 统计数字、空状态、图标按钮等）同样是深色字压深色壁纸。

## 2. 缺陷现象描述

1. 套用深色壁纸后，顶部一排文字与右上角窗口按钮"看不见/点不到"；
2. 页面局部区域（侧边栏、图标按钮、空状态标题）同样是黑字压黑底；
3. 换成浅色壁纸时也偶发"白字压浅底"的反向问题。

## 3. 期望表现（规范定义）

1. 顶部文字在任何壁纸下都必须可读（对比度 ≥ 4.5:1）；
2. **原生最小化/最大化/关闭按钮必须始终存在**（这是可用性底线，不能为了沉浸感牺牲）；
3. 透明面板上的文字需按「实际压在什么颜色上」自适应，不透明面板（设置弹窗等）内保持原生配色。

## 4. 根本原因深度分析（代码级诊断）

### 4.1 窗口按钮消失：WCO 底色被设成了全透明
- **文件位置**：`client/modules/wallpaper.js` → `syncTitleBarOverlay()`
- **诱因**：为了"右上角三个按钮完全透明融入壁纸"，代码把 `setTitleBarOverlay({ color: 'rgba(0, 0, 0, 0)' })` 写死。Windows 的 Window Controls Overlay 在底色完全透明时会**整体隐藏**按钮（实测 `visible: false`），用户于是无法最小化/关闭窗口。
- **A/B 实测**：换回官方 `app.asar` → `visible: true`（标题栏区域 1263×30）；套用本主题 → `visible: false`。
- **同源问题**：`client/modules/boot-animation.js` 与 `loadingOverlay.js`（注入主进程的 asar 补丁）也把 `color` 设为 `'rgba(0,0,0,0)'` / `'#00000000'`。

### 4.2 顶部文字黑压黑：字色跟「原生主题」而不是「壁纸」
- **文件位置**：`client/styles/glass-theme.css` 第 2.6 节
- **诱因**：规则写死 `[data-testid="title-menu-bar-item"] { color: #000000 !important }`（浅色主题分支），而这条规则只看原生主题，完全没看壁纸明暗。
- **放大因素**：全局亮度探针只算「整张壁纸的平均亮度」（earth = 0.247 → 判为浅色壁纸），**但标题栏所在的最顶部条带实测只有 0.011**。用平均值决定顶部字色，必然是反的。

### 4.3 「一些页面」看不清：缺少通用对比度兜底
- 第 15 节的自适应层只覆盖会话区（输入框 / 气泡 / AI 回复），侧边栏、图标按钮、Overview 面板、空状态等仍沿用浅色主题的深色字，压在深色壁纸上。

## 5. 修复方案（技术执行路径）

1. **WCO 必须不透明**（`wallpaper.js` / `boot-animation.js` / `loadingOverlay.js`）：
   - 开机阶段：`#000000` + 浅色符号（与纯黑幕布无缝衔接，按钮全程可见）；
   - 主界面：按壁纸**顶部条带**明暗给两套配色（深：`#0b0f19` + `#e8eef7`；浅：`#f4f6fa` + `#1c2430`）；
   - 主进程在幕布移除后同步一次，并在窗口 `focus` / `restore` 时跟随壁纸变化。
2. **顶部条带独立测量**（`client/index.js`）：32×32 缩略采样时额外统计最上方 9% 条带的相对亮度 → `dataset.agyTopLum` + `html.agy-dark-topbar / agy-light-topbar`。
3. **顶部文字改为跟随顶部条带**（CSS 2.6）：深浅两套字色 + 文字阴影 + 一层 42% 的极淡渐变蒙层兜底（`pointer-events:none`，不挡点击）。
4. **通用对比度守护**（`Contrast Guard`，`client/index.js` + CSS 第 17 节）：
   - 逐个「含文本 / 图标」元素求**最近的不透明祖先背景**（纯色按 alpha、渐变按 alpha 加权解析），找不到就按**纵向 8 段亮度剖面**取元素所在高度的壁纸亮度；
   - WCAG 对比度 < 3:1 才给元素打 `data-agy-cg="light|dark"` 并写 inline `!important` 双保险，原色记录在 `__agyCgOrigFg` 便于回滚；
   - **判定永远基于原始字色**（不能拿改完的浅色回算，否则会「翻完→显得够亮→再翻回去」无限抖动）；
   - 结构变化用 `MutationObserver`（1.2s 防抖）增量重算；不透明浅色面板（设置弹窗实测 `rgba(235,238,243,0.96)`）自动判定为"已达标"，实测误伤 **0** 处。

## 6. 验证与验收标准

- [x] `navigator.windowControlsOverlay.visible === true`，标题栏区域 1263×30 恢复；
- [x] 顶部菜单实测字色 `rgb(242,246,252)` + 阴影，对比度 > 18:1；
- [x] 顶部图标按钮（更多操作 / 切换侧边栏 / 后退等）由 `rgb(0,0,0)` 变为 `rgb(244,247,251)`；
- [x] 对比度守护稳定态 36 个元素翻色，连跑 3 次结果完全一致（`stable: true`，无抖动）；
- [x] 设置弹窗等不透明浅色面板内文字保持深色，误伤 0 处；
- [x] 壁纸改为浅色时反向翻成深色（同一套逻辑）；
- [x] 开机动画、动态壁纸、毛玻璃等功能不受影响。

## 7. 修复与复盘记录

- **修复方案摘要**：WCO 由"强制透明"改为"跟随壁纸顶部明暗的不透明配色"；新增顶部条带亮度测量与 8 段纵向亮度剖面；顶部菜单字色改为跟随壁纸（+ 蒙层兜底）；新增通用对比度守护（含图标按钮）并解决抖动与 React 重渲染覆盖问题。
- **复盘**：
  1. **「透明化」类需求必须先确认平台底线**：Windows WCO 不支持全透明，透明 = 按钮消失，属于可用性事故；
  2. **明暗判定要看「局部」而不是「全图平均」**：标题栏压在壁纸最上方，必须单独采样条带；后续所有「按壁纸调色」的地方都应使用纵向剖面；
  3. **自适应上色必须基于原始颜色判定**，否则会自我震荡；
  4. 主题 CSS 里任何 `color: #000 !important` 都可能成为「黑压黑」的元凶，自适应配色不该由原生主题单方面决定。
