# BUG-018: Windows客户端开屏动画退出进入首页出现450ms黑屏停滞一闪而过

- **缺陷编号**：`BUG-018`
- **涉及需求 / 模块**：Wallpaper素材库集成 (`loadingOverlay.js`, `patch-boot-overlay.mjs`, `client/modules/wallpaper.js`)
- **严重级别**：P1（视觉体验断层与黑闪）
- **当前状态**：`已修复`
- **发现时间**：2026-10-24
- **修复完成时间**：2026-10-24
- **报告人**：用户实机测试反馈

## 1. 缺陷现象描述
用户在 Windows 平台配置了开机引导动画并开启了动态壁纸（无论是纯视频壁纸还是 WebGL 场景壁纸）。
在开屏动画播放完毕点击“进入工作区”或按下 ESC 键退出时，**画面出现明显的黑色一闪而过（持续约 400~500 毫秒的完全黑屏停滞）**，随后具体页面与壁纸才突兀显现。

## 2. 期望表现
用户点击“进入工作区”或倒计时结束时，应直接秒级切入已 100% 满血成型的主界面与 60fps 动态壁纸，全程零黑屏停留、零视觉闪烁。

## 3. 根本原因深度分析
1. **WebContentsView 跨进程透明穿透失效**：
   在 `loadingOverlay.js` 的退出函数 `finish()` 中，原代码试图通过 CSS `stage.style.opacity = '0'` 实现淡出，并硬编码了 `setTimeout(..., 450)` 等待淡出完成后再调用 `removeChildView(view)`。
   但在 Windows DirectComposition 架构下，独立的 `WebContentsView` 无法对下层的主窗口实现透明 Alpha 混合。`stage` 透明后，暴露的是该 View 自身的 DirectComposition 黑色缓冲区；用户眼睁睁看着纯黑底板持续了 450 毫秒，待定时器触发移走 View 时，主窗口才突然露出来。
2. **`v.load()` 暴力清空解码帧**：
   在 `client/modules/wallpaper.js` 中，唤醒壁纸视频遇到 Chromium 拦截重试时误调用了 `v.load()`，把浏览器已就绪的首帧当场清空，瞬间回退到黑底。

## 4. 实施修复方案
1. **彻底拔除 450ms 纯黑延迟盲等**：
   在 `loadingOverlay.js` 的 `finish()` 中，点击退出的第 0 毫秒立即发送 `__AGY_BOOT_DONE__` 并移走遮罩盖子；直接无缝承接底层早已 60fps 满血运转的动态壁纸与具体主工作区。
2. **剔除清帧调用**：
   移除了 `wallpaper.js` 中的 `v.load()`，改用无损 `play().catch()`，确保壁纸首帧画面始终纹丝不动常驻。
3. **充分预跑保护**：
   将场景壁纸冷启动就绪判定阈值恢复至稳健的 1000ms（整整 1 秒）。

## 5. 验证与验收标准
- [x] 1. 纯视频壁纸冷启动，点击或到点退出开屏动画，彻底消除黑色一闪而过；
- [x] 2. 场景壁纸冷启动，点击或到点退出开屏动画，无黑屏停留，秒级直达首页；
- [x] 3. 外观面板“⚡ 一键修复”与 `patch-loading.bat` 已同步包含本修复。

## 6. 归档与封版
- **归档状态**：`已封版归档`
- **归档时间**：2026-10-24

## 7. 修复与复盘记录
- **修复方案摘要**：
  1. 彻底剔除 Windows 主进程 `loadingOverlay.js` 中人为设置的 450ms 纯黑延迟，点击第 0 毫秒立即移走 View，无缝展示已渲染好的主界面；
  2. 修复 `wallpaper.js` 中 Chromium 拦截唤醒时误调用 `v.load()` 导致的视频首帧清空；
  3. 将后台 Shader 预跑时间恢复至 1000ms，双保险杜绝出帧卡顿。
- **效果验证**：✅ 经用户实机确认，纯视频壁纸与场景壁纸下，退出开机动画进入首页均彻底告别黑色一闪而过，实现真正点击秒进。已正式封版归档。
