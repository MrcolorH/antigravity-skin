# BUG-016: 开屏引导动画与宿主主页加载冲突（双重动画、早泄穿帮与首帧无缝呈现闭环）

- **缺陷编号**：`BUG-016`
- **涉及需求 / 模块**：Wallpaper素材库集成 (`loadingOverlay.js`, `sidecars/skin-engine/main.mjs`, `client/index.js`, `client/modules/boot-animation.js`, `client/modules/wallpaper.js`)
- **严重级别**：P1（核心启动体验与视效闭环）
- **当前状态**：`已修复`
- **发现时间**：2026-10-23
- **修复完成时间**：2026-10-23
- **报告人**：用户实机测试

## 1. 缺陷现象描述
1. **白闪与早泄穿帮**：开机阶段先纯黑，随后主进程遮罩过早销毁，裸露主窗口空白原生背景并闪烁；前端随后又拉起第二个开屏动画，用户需点击两次才能进首页；
2. **黑屏与现场拼凑**：用户点击开机动画淡出后，出现长达 1 秒黑屏，随后眼睁睁看着输入框、侧边栏及动态壁纸在视口中现场拼凑加载，开屏动画失去遮掩加载的本质意义；
3. **冷启动盲等等待**：Sidecar 在冷启动极早期未捕获到调试端口时默认等待 2000ms 重试，导致插件握手白白滞后 2 秒。

## 2. 期望表现（规范定义）
1. **T=0 秒直接秒播开机动画**：窗口弹出的第一毫秒，主进程直接拉起全屏开屏视频硬解秒播，零黑屏过渡，零白闪；
2. **真·完整就绪铁壁防线（Truly Ready）**：开屏动画必须在后台忠实遮蔽构建过程，严格等待 React 主输入框、插件脚本、4K 动态场景壁纸活态帧与毛玻璃样式全部 100% 渲染就位后才允许胶囊变绿；
3. **一键直达首页**：彻底切除前端多余的第二次开机动画，点击一次直接平滑溶出进入 100% 满血成型的首页，绝无黑屏与拼凑；
4. **内核事件驱动秒连**：Sidecar 建立 `DevToolsActivePort` 目录级 `fs.watch` 与冷启动 100ms 自适应快频重试，直接砍掉 1.5 ~ 2 秒盲等时间。

## 3. 根本原因分析
1. **早泄放行导致穿帮**：旧版判定仅检查 `childElementCount >= 2`，在 React 刚生成两个空容器时就误判就绪，导致开屏动画在首页还是半成品时提前移开；
2. **跨上下文会话隔离**：主进程向 `about:blank` 写入的 `sessionStorage` 未能继承至真实 App Origin，前端误判为首次冷启动，重复触发了第二次开机动画；
3. **探测重试周期过长**：Sidecar 启动时如果遇到端口文件正在创建，固定等待 2000ms 重试，白白浪费 2 秒黄金冷启动期。

## 4. 实施修复方案
1. **主进程全链路广播锁**：
   - 在 `loadingOverlay.js` 中于导航、DOM 装载及淡出等每一个生命周期向主窗口广播注入 `window.__agyMasterBootHandled = true; sessionStorage.setItem('__agy_booted__', 'true');`；
   - 前端 `client/index.js` 与 `boot-animation.js` 严格检查该全局锁，冷启动时坚决不二次触发开机动画。
2. **真·完整就绪多维判定**：
   - 必须检测到 `textarea` / `[contenteditable]` 等主交互区域真实挂载；
   - 必须确认 `window.__AG_SKIN_ATTACHED__ === true`；
   - 动态场景壁纸必须已跑通 `canvas.agy-scene-live` 活态帧并稳定运行；
   - 毛玻璃样式 `#agy-dynamic-wallpaper-style` 必须已生效。
3. **内核文件监听与自适应快频重试**：
   - 在 `sidecars/skin-engine/main.mjs` 中加入对 `DevToolsActivePort` 所在目录的 `fs.watch` 内核事件监听，端口生成 0 毫秒即刻响应；
   - 冷启动前 8 秒内将重试探测间隔压缩为 100ms，直接砍掉 1.5 ~ 2 秒盲等时间。

## 5. 验证与验收标准
- [x] 1. 开机第一帧直接呈现满屏开机视频，消除所有前置过渡闪烁与白闪；
- [x] 2. 状态胶囊精准遮掩，主工作区与场景壁纸完全渲染就绪后才变绿；
- [x] 3. 点击一次即 450ms 平滑溶出进入完整首页，彻底消除中间黑屏与二次动画；
- [x] 4. 内核文件监听生效，消除 2 秒轮询盲区；
- [x] 5. 静态检查全部通过，补丁与插件全量同步。

## 6. 复盘与总结
- 开机引导动画的本质是“**为重型应用的冷启动初始化提供优雅的视觉遮盖**”。其生命周期的终点必须严格锚定在“**宿主页面核心交互框架与媒体底板 100% 满血就绪**”的真实时间点上，既不能被长连接拖累死等，也绝不能因轻率放行导致半成品穿帮。
- 引入内核级文件监听（`fs.watch`）与自适应探测周期，在保障 0% CPU 闲置占用的同时，最大化消除了冷启动盲等延迟。
